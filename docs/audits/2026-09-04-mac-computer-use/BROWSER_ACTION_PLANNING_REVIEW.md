# Choose native form actions in the default research driver

Parent: `221e46c`. This checkpoint connects an input-bound action selector and the existing form planner to the default research driver and shared local runtime. The source now sequences ordinary native form editing, verified GET queries and result reading under the original goal. Current compilation, model accuracy and browser behavior remain unqualified.

## First-principles findings

The previous driver could recover a form stage but could not decide to start one. It interpreted each newly visited page as a result page and asked for another link. That is insufficient for a travel or ticket site whose next useful step is entering search criteria.

A form is also not an instruction to fill it. The same page may contain a useful search, an unrelated newsletter signup and an account form. The next capability must be chosen against the complete request and current evidence before preparing fields. A separate value proposal must then respect the chosen form, exact source text, host-derived values and native option identities.

Historical typing is not current field state. The selector needs to know that a verified stage exists so it does not repeat edits solely because values are hidden. Actual query execution must still recheck the original fields and receipts. Field rediscovery is especially consequential: the current native discovery operation clears earlier input receipts, so automatic dependent stages cannot safely use that path without further work.

## Source changes

- `ComputerUseBrowserActionInput` retains the entire interpreted goal, original request/clock, accepted answers, ordered requirement source spans and a bounded current-page projection. Existing native `form_id` grouping identifies eligible observed forms. The context includes historical navigation/form counts and, when applicable, the latest verified edit stage on this exact native document with its motivating requirement indices. Private URLs, submission names, current field values and native document/operation authority are omitted from model context.
- A strict action proposal chooses exactly one alternative: read results, prepare an offered form, open a candidate query from the verified edit stage, ask a scoped typed question, or report that no supported next step can be justified. It has no arbitrary URL, executable command, field value, free-form question or completion alternative. Foreign references, duplicate/extra keys, mixed alternatives and invalid question scopes are rejected. Query choices are tied to the original native form receipt; they are not current-value certificates.
- The local action planner uses exact full-request token admission, authenticated loopback transport, strict schema and the existing output/context limits. It does not truncate the task. If no supported form/query choice is offered, the native adapter returns the read-results decision without starting another inference request. When a form decision is needed, the same model process and lease are used as the existing planners.
- The research owner observes and plans within one operation, validates proposal/input identity and revalidates the actual page before publication. Pause invalidates speculative action references and holds ownership until the planner unwinds. Reading, questions, source changes and later preparation invalidate earlier speculative choices. Query entry consumes the current action and creates the existing retained query intent before any navigation work.
- Form preparation consumes the selected action's exact native observation, validates it before field discovery, binds actual fields and records the selected form. Form context version 3 distinguishes aliases eligible for editing from aliases retained for explicit user preservation. The decoder and strict model schema restrict edits to the selected form. Other bound fields cannot receive edits through that proposal; a preservation reference is still only a semantic proposal that must correspond to the user's actual requirement.
- The driver now chooses a capability before result grouping when a page may need form interaction. A form choice prepares native fields, obtains an exact form proposal, routes a scoped question if necessary and executes the retained text stage. The next decision can open its verified native GET query, then continue reading/assessing results and choosing links. Pending form input now reconciles and returns to this decision loop instead of stopping merely because form-action selection was missing. Query history, the original clock, source policies, accepted answers and the full task survive these transitions.
- Driver construction requires action and form planners explicitly. The production loader supplies both shared-runtime adapters. Existing focused driver fixtures explicitly supply their own proposals; there is no hidden read-only fallback in the production initializer. A form-stage limit bounds repeated edit decisions, and existing navigation limits still apply. Neither kind of intermediate work declares a completed research answer.
- A second automatic edit stage on the same native document currently returns an intervention before rediscovery can erase earlier receipts. The original verified stage remains available for a justified query. This is a temporary capability gap, not dependent-form support. Existing unscoped preparation APIs remain available to their earlier callers/tests; the new automatic action path does not silently use them to discard earlier authority.
- Form receipts now include the root digest, allowing action history and query construction to reject receipts from a different original goal. An existing unrun query-refresh test was corrected: changed form-action metadata is already part of native page equality, so that mutation is rejected as a changed page before the later destination comparison.

The selector's semantic judgment remains a model proposal. Native form correspondence and exact payload provenance cannot independently prove that a field or option means what the model thinks. The default driver still cannot assemble a verified research answer.

## Prepared regression coverage

Eleven new methods cover complete goal/clock/source context without private values; strict action decoding and foreign inputs; cancellation and stale action references; selected-form edit boundaries versus preservation aliases; verified query offerings and receipt preservation when dependent discovery is unavailable; exact context admission and zero transport calls when no form decision is needed; transport cancellation; the complete driver form → input → query → result-reading path; a scoped form question and accepted answer; Pause during form planning; and recovery after a committed input without another form proposal or repeated typing.

Driver scenarios use deterministic proposal fixtures over loopback pages. They exercise the production composition in authored source, but they do not qualify a real model. Existing fixture dependencies and the previous pending-form recovery expectation were updated for the new decision loop. No held-out qualification data was inspected or changed.

## Remaining repair order

1. **Implement retained dependent-field discovery and aggregate continuation.** Reobserve the same native objects, add newly exposed fields without clearing earlier receipts, preserve prior expected values where the goal still requires them, and combine verified stage evidence before query preparation. Handle legitimately changed dependent values explicitly. Remove the temporary automatic-stage guard only when those rules are implemented and qualified.
2. **Scope native discovery to the selected form.** The current binding still discovers the page's supported fields before restricting editable aliases. An unrelated unlabelled field or more than sixteen supported fields across the document can prevent a valid selected form from being prepared. Bind discovery directly to the observed native form while retaining source/page/membership checks and explicit preservation requirements.
3. **Recover changed unsent work and login documents.** Equivalent unsent query refresh exists; arbitrary changed forms and new documents cannot inherit old field authority. Replan under durable/native no-attempt proof and an atomic binding update. Finish visible account/provider-window handoff and explicit host/phone return of control, preserving unresolved attempts and the original research goal.
4. **Complete durable parent recovery and cleanup.** Per-stage journals do not reconstruct the ordered goal graph, remaining requirements, archived readings, pending intent or browser state after process loss. Finish persistence/reconciliation and unresponsive WebKit/process lifetime bounds.
5. **Extend actual browser capabilities.** Native typed formats do not cover general date/time ranges, airports/location transformations, richer party/inventory quantities, autocomplete, calendar/custom widgets, POST/dynamic submission, embedded controls or canvas-based interfaces. Preserve whole-goal semantics as those capabilities are added.
6. **Complete result verification and answer assembly.** Offer association, distinct qualifying counts, availability, quantities, fees, ranking, public source links and complete requirement accounting remain open. A loaded query, numeric match or second model interpretation is not proof of those facts or a completed answer.
7. **Qualify the default pipeline after authorization.** Typecheck/build, run bounded native checks, qualify current action/form/result prompts and then perform the deferred travel/concert/movie website scenarios. Test whether the lightweight model correctly chooses reading versus form work, handles negation/preservation/answers and avoids repeated edits. Separate application defects from model errors before changing models or using the authorized RTX 3080 desktop for adaptation. Keep held-out data separate and retain the 8 GB Mac target; remote access remains unverified after the earlier timeout.
