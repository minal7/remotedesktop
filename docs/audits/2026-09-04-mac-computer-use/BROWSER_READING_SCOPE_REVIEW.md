# Read task-relevant text controls under a fresh scope

Source checkpoint, 2026-09-08. Previous checkpoint: `8a94417`. Execution remains deferred.

## First-principles defect

Research needs to know the criteria currently selected on a page, as well as what its results say. The preceding reader captured dates, numbers and native selections but omitted every text-entry value. A location field showing Paris therefore remained unknown even when the request explicitly concerned Paris. Treating that field as irrelevant would conceal a potentially conflicting filter. Collecting every field would instead expose unrelated account or contact values before establishing a task purpose.

The necessary sequence is metadata, proposed task scope, fresh native validation, bounded value observation, and separate result assessment. A task reference establishes which requirement motivated a read; it does not prove that the model selected the semantically correct control. Reading a setting also does not establish that a provider applied it. The [preceding result-provenance boundary](BROWSER_SELECTION_RESULT_REVIEW.md) remains necessary.

## Source implementation

- [The existing action planner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserActionPlanner.swift) can choose `read_results` with one to sixteen unique `read_controls` references. Each contains an offered native control ID and an original requirement index. Eligible requirements are outcome/condition clauses interpreted as category, origin, destination, location, date, time or quantity. Selection occurs before text values enter research context. The closed response rejects unknown references, duplicate controls, values, mixed action alternatives and prohibited requirement roles. Ordinary `read_results` retains its previous meaning.
- Only rendered, projected, labeled, enabled native text/search inputs with a native eligibility flag are offered. [Eligibility checks](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserDOM.swift) exclude supported credential/account/contact/payment/birth-date metadata and autocomplete markers, plus read-only inputs. The protection check now also precedes ordinary scalar/selection/checked value reads: numeric card fields and date-of-birth fields could otherwise pass the older general reader. This is a metadata-based exclusion boundary, not universal private-data recognition across arbitrary labels or languages.
- [The scoped reader](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserReadingScope.swift) binds the proposal to the task document, current presentation and source policy. The native command first rechecks the complete prior snapshot, URL, viewport, containers, links, native controls and their form identities. It validates every requested control before collecting any newly requested text value. The read uses captured native input-value getters in the same synchronous invocation. Each value is retained whole up to 2,048 UTF-8 bytes; unsupported or oversized values remain unavailable.
- The resulting snapshot carries the ordered scope IDs and `text` control states. Native decoding requires a bounded, unique, eligible scope and rejects text states outside it. The existing overall observation and planner-projection budgets remain. Subsequent validation re-reads the same scope, including property-only value changes that produce no DOM mutation or input event. Starting an ordinary observation clears the scope. The old metadata snapshot cannot authorize a second read after its snapshot ID has been consumed.
- [The research owner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) accepts only its exact latest action under the current goal/interpretation. It consumes that action before reading and keeps the normal operation ownership, cancellation checks and DOM completion joining. [The driver](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchDriver.swift) passes the chosen action through its existing read-results path. Pause and explicit handback invalidate the old action; continuation needs fresh metadata and a new scope under the retained original task.
- This reuses the existing action decision instead of adding a separate model call. A page with eligible text controls now needs that decision even if it has no editable form. Action context/schema uses version 8 when scoped reads are offered; page projection uses version 5 when scoped text states are included. Other action/page versions remain available for their existing modes. Result and review output schemas retain their existing control-reference contracts.
- Scoped text remains native **control state**, with complete control metadata and the existing candidate/container association checks. It cannot supply positive result support or an exact offer price. Matching location or date settings still need independent result facts. Whole control observations remain separate from quoted page prose in an informational answer.
