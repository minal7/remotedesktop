# Return to earlier research pages under native navigation authority

Source checkpoint, 2026-09-08. Previous checkpoint: `c99e6ba`. Execution remains deferred.

## First-principles defect

Research is not a single chain of forward links. To compare two tickets, the browser often needs to read one detail page, return to the result list and open another. The preceding implementation could combine explicitly recalled observations in an answer, but its planner could only follow a current link, work with a form or read stored evidence. Reading an earlier observation does not move the browser. A detail page without a useful next link could therefore strand the task even when the required result list was already in browser history.

Returning also has two different meanings. Traversing an existing history entry can preserve its document and the forward list. Loading its URL again starts a new navigation and can discard the forward branch. Recovery must not silently substitute one for the other. Neither operation proves that an old ticket price remains available, that login succeeded or that the original request is complete.

## Source changes

- [The native browser](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseOwnedBrowser.swift) retains the exact `WKBackForwardListItem` associated with a successful native navigation receipt. An entry becomes eligible only after a successful page observation, and only when that navigation's observed requests remained GET/HEAD. Options come from this task's confirmed visits and browser context, under the current source policy. Arbitrary user history, unobserved login pages and an invented model URL are not offered by this registry. URL and object checks remain native.
- Options identify an earlier visit by ordinal. The host classifies it as `back`, `forward` or `revisit`, deduplicating destinations and excluding the current URL. Retained items use `WKWebView.go(to:)`; an evicted item requires an explicitly selected new GET to its saved destination. Apple exposes history through [WKWebView.backForwardList](https://developer.apple.com/documentation/webkit/wkwebview/backforwardlist) and [WKBackForwardList](https://developer.apple.com/documentation/webkit/wkbackforwardlist?language=objc). The exact current item, back list and forward list determine native traversal eligibility, rather than a model-authored history offset or script.
- Both paths reuse the observed-navigation transaction, durable attempted/verified journal, execution lease and native receipt reconciliation. The original task digest and a distinct stage operation ID survive Pause. Fresh rebinding is allowed only after proof that the original effect was unsent. It keeps the same selected visit, destination, browser context, source policy and traversal-versus-GET mode. An attempted or uncertain operation cannot be replaced by another operation ID to retry it.
- [The retained history stage](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchHistoryNavigation.swift) preserves an alternative target when a replacement journal write has an unconfirmed outcome. Existing journal resolution decides which target remains authoritative before continuing. A completed stage can return its historical receipt without another navigation. Retirement and cancellation retain the existing ownership rules; DOM completion is joined before releasing a failed preparation or validation.
- Before dispatch, native validation checks the exact current page, selected historical object or saved revisit, destination and source policy. Checks run again around the durable dispatch callback. A new non-GET/HEAD request during a history traversal is rejected. Ordinary completion retains the native navigation identity and response checks. Cached restoration can complete with the exact retained history item, matching URL and settled loading state; the macOS 26 Instant Back path additionally requires its specific delegate approval before the bounded restoration poll can finish it. The normal navigation deadline and cancellation apply to this poll. Actual callback ordering and cached-page behavior remain unexecuted.
- [Action planning](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserActionPlanner.swift) now offers history destinations before reading, using input version 7 and schema `browser_research_action_v7`. [Result planning](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserLinkPlanner.swift) offers them after reading, using input version 8 and schema `browser_result_link_v5`. Both accept only the closed object `{"revisit":N}` with an offered integer visit index. Native history and current-page bindings validate the ordinal. Legacy link-only replan contexts cannot choose a different capability while their original effect is pending.
- Planner context includes the full original request, accepted answers, navigation order, mode and associated archived reading indices. The exact destination and native operation ID do not enter the model's history projection. Earlier contents require explicit recall when needed. Prompts distinguish recall, navigation and fresh evidence, and require the selected step to advance the remaining request without inferring permission from page instructions.
- [The research owner and driver](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) retain pending history work before allowing another selection. Confirmed returns enter the same task history as searches, links and form queries. They count toward the existing total navigation limit. The next driver iteration observes the current page and considers the original request again. Login still requires visible manual control and explicit handback. Earlier answer readings remain invalidated across that handoff until fresh observations support them.

A successfully observed GET destination is not a proof that a website has no side effects. Site scripts and server behavior still need qualification, and semantic relevance remains a planner responsibility. This repair does not permit arbitrary POST replay or provide a general guarantee about provider navigation semantics.
