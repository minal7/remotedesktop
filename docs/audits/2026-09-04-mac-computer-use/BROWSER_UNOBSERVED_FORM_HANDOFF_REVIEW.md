Source repair; execution pending. This follows the [manual login request history repair](BROWSER_LOGIN_REQUEST_HISTORY_REVIEW.md). No build, typecheck, assertion, app, browser, model or account-login execution occurred.

## First-principles defect

A form preparation is published before its first private read so cancellation cannot erase a dispatched capture. That ownership rule is necessary. However, a preparation that never reached any private observation could remain tied to an old document after manual sign-in. Both ordinary preparation and criterion recovery restore the original native page. After a redirect, both can fail against the same stale document, leaving an unused initial plan with no way to return to fresh planning.

Absence of input is insufficient to release every preparation. A read can have captured a baseline; an earlier stage can carry receipts; a preservation or inspection choice can carry a duty even before its value is read. An incomplete callback is uncertainty, not absence. These cases need their existing reconciliation paths.

## Narrow release rule

The [preparation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormPreparation.swift) exposes eligibility only when all of the following hold:

- It is an initial frame with no parent, prior continuation, revision, captured baseline, inherited capture or criterion repair.
- Its review has no added duties, preservation sources, read sources or retained-field purposes. Its original page is metadata only, without observed or scoped control state.
- It has no fields, bound evidence, preservation state, prepared input or started binding/preservation read. The target has no document binding, input ledger, field mapping or preservation guard.
- The initial field capture either never started or has the existing validated empty authentication failure. Pending reads, cancellation, ordinary failure, successful capture and recovered revision results cannot prove absence. Inspecting this fact does not reset the retained callback.

The authentication exception uses the existing native pre-value authentication barrier and reply decoder. It does not generalize arbitrary failures into proof that no observation occurred. The existing malformed-authentication-reply cases continue to reject replies containing private preparation data.

The [owner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) separately requires a successful explicit Resume that actually observed a different native DOM document in the same browser context. It retains the checked native document and the complete goal revision only after session, cancellation and control-epoch validation. Pause and owner retirement clear this seal. A final pure epoch check also prevents a reentrant Pause inside the action gate from publishing a successful Resume.

Recovery observes the current page under the current source policy and requires both its document object and native DOM identity to match that successful handback observation. A subsequent navigation cannot reuse the seal. The page receives a fresh native validation; a failed validation joins its DOM callback before the owner operation ends. Final cancellation, ownership, preparation-identity and pure Pause checks precede publication.

Only then does the owner record the unused purposes and clear that preparation. It does not create an input stage, query receipt, retirement journal or verified form receipt. Earlier histories remain intact. The existing driver recovery loop can return to ordinary complete-goal action planning; a fresh form still needs scope review, native field discovery, planning and verification. The first actual input stage keeps index zero when no prior stage existed.

## Historical context

[Action context](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserActionPlanner.swift) version 28 includes `unobserved_form_intent_history`, also on pages without a form. This prevents the no-decision shortcut from skipping the unused intent. Each record preserves historical public field labels/kinds, dispositions and exact user-source spans, without old control IDs, target mappings, private values, private page URLs or action capabilities.

`values_observed`, `input_dispatched` and `current_field_verification` are false for these preparations. Instructions require the complete current request and fresh page evidence to determine the next action. Old labels remain untrusted page data; source overlap is not semantic equivalence. The history is neither login proof nor proof that a criterion is satisfied.

Records require ordered indices, the same session context and complete original/retirement goal ancestry. The owner retains at most 32 records. Reaching that bound leaves the preparation on its existing recovery path; it does not discard history or authorize a different operation. Existing planner prompt limits still apply. Owner retirement clears this live history.
