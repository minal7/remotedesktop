# Source-bound planner: findings and next repairs

The experimental compiler improves reference integrity, but it does not establish semantic authority. The unchanged v6 candidate passed all 14 known complete-sequence regressions. Its new corpus exposed an accepted incorrect edit: “Write a warm welcome in Notes.” became the literal value `a warm welcome`. Every word was present in the request, the target was correct, and source coverage was complete. Those facts did not make the edit the requested outcome. This proposal-only test executed no desktop effects, and the candidate remains outside production.

Two other saved failures were conservative rejections. The planner resolved “the same field” to `Notes` but supplied that label as a source reference where only the pronoun occurred. For “Copy the current value of Title into Tag,” it proposed `f1` as an input value instead of declining the unsupported read/copy operation. The host rejected both. These failures differ from the accepted semantic error and need separate measurements.

The first holdout run also exhausted disk space while saving its nineteenth result. Eighteen records survived; an unchanged-candidate continuation supplied the remaining two records. H519 was reattempted because its first result was not durable, and H520 received its first inference. Complete accounting is **16/20**: three rejected-plan failures and one accepted incorrect plan. H520 confirmed that the compiler wrongly treated a forbidden value as a requirement to preserve the entire field. See [the complete accounting and separate run records](source-bound-text-v6-heldout-results.json). A broken result bundle cannot establish a passing test run, and this candidate fails qualification on the model results independently of the disk failure.

## Repair order

1. **Represent what the user wants before choosing text effects.** The task contract needs distinct outcomes for entering supplied text, generating writing, copying observed data, preserving state and other operations. “Write a warm welcome” requests generated content; “Type the words ‘a warm welcome’” supplies literal content. Classifying both as text insertion loses the distinction that determines the correct result. Add the accepted H516 failure as a permanent regression. Keep this finding open until actual-model unseen requests demonstrate the intended distinctions.

2. **Give every payload an explicit origin.** Use typed references for host-captured literals, exact unquoted spans, a generated draft step, and a reviewed observation of a source field. A generated draft or existing field identifier must never silently become an exact-literal payload. Generation and copying need their own authorized dependencies and outcome checks; the current exact-form capability should decline them completely. A source span remains supporting evidence, not an independent proof that the user requested its literal insertion.

3. **Offer source references that the host can bind directly.** The current global target enum allows a label from an earlier clause even when the current clause contains only a pronoun. The model then fails the later host check. Supply bounded mention identifiers with source locations and candidate field identities, including explicit back-references. Retain ambiguity handling and the unique preceding-target rule. Do not repair this by accepting any field ID or treating an absent label as an implicit mention.

4. **Model constraints at their actual scope.** Leaving a field unchanged and prohibiting a particular value are different requirements. A field can be changed to an allowed value while respecting a forbidden-value constraint. Compile explicit constraints into predicates on the relevant operation or final state, and test them independently of the model's classification. Do not infer that an empty constraint list proves a prohibition was respected.

5. **Use compiler feedback for bounded recovery.** The current one-retry source-coverage correction recovered the omitted unchanged-field sentence in the known corpus. Preserve its exact token counting, cancellation checks, original task authority and complete second-pass validation. If feedback expands to reference or intent errors, distinguish those diagnostics, record each attempt, and measure the effect on false acceptance as well as completion. Extra attempts cannot substitute for a correct contract.

6. **Keep every effect visible to the oracle.** Check complete allowed operation vectors, including repeated actions, target, mode, exact bytes and order. In the real browser fixture, independently record the target and both field values after each input event. A correct final value and even a correct event count can hide an incorrect intermediate effect. Include mutation of fields that should remain unchanged and Unicode normalization in the oracle's rejection tests.

7. **Qualify before switching production.** Preserve the frozen candidate, first-run failures, incomplete infrastructure run and continuation as separate evidence. Any corpus used to revise the next candidate becomes regression data. Test fresh phrasing before adoption, then exercise the selected planner through the actual coordinator and browser/native adapters. Zero accepted incorrect plans in this corpus is a necessary gate; a small passing corpus does not establish general natural-language reliability, mobile transport, interruption recovery or release readiness.
