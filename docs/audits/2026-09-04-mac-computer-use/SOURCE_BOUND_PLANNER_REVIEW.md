# Source-bound planner: findings and next repairs

The experimental compiler improves reference integrity, but it does not establish semantic authority. The unchanged v6 candidate passed all 14 known complete-sequence regressions. Its new corpus exposed an accepted incorrect edit: “Write a warm welcome in Notes.” became the literal value `a warm welcome`. Every word was present in the request, the target was correct, and source coverage was complete. Those facts did not make the edit the requested outcome. This proposal-only test executed no desktop effects, and the candidate remains outside production.

Two other saved failures were conservative rejections. The planner resolved “the same field” to `Notes` but supplied that label as a source reference where only the pronoun occurred. For “Copy the current value of Title into Tag,” it proposed `f1` as an input value instead of declining the unsupported read/copy operation. The host rejected both. These failures differ from the accepted semantic error and need separate measurements.

A subsequent comparison ran these four failed requests through the current `candidate-v2` planner, without effects or the quoted-command compiler. It passed **3/4**: the pronoun edit was correct, and copying/generated writing were declined correctly. The prohibited-value request conservatively received clarification. Thus the accepted generated-writing error and two other failures were regressions of experimental v6. This was a diagnostic selection after observing failures, not a new holdout. See [the baseline comparison](native-text-v2-failure-comparison-results.json). Stronger invariants are useful only if the added representation preserves the task's meaning.

The first holdout run also exhausted disk space while saving its nineteenth result. Eighteen records survived; an unchanged-candidate continuation supplied the remaining two records. H519 was reattempted because its first result was not durable, and H520 received its first inference. Complete accounting is **16/20**: three rejected-plan failures and one accepted incorrect plan. H520 confirmed that the compiler wrongly treated a forbidden value as a requirement to preserve the entire field. See [the complete accounting and separate run records](source-bound-text-v6-heldout-results.json). A broken result bundle cannot establish a passing test run, and this candidate fails qualification on the model results independently of the disk failure.

## Repair order

1. **Represent what the user wants before choosing text effects.** The task contract needs distinct outcomes for entering supplied text, generating writing, copying observed data, preserving state and other operations. “Write a warm welcome” requests generated content; “Type the words ‘a warm welcome’” supplies literal content. Classifying both as text insertion loses the distinction that determines the correct result. Retain the current semantic planner as a measured baseline and evaluate additional binding/verification separately, so a proof-producing representation cannot silently reclassify the request. Add the accepted H516 failure as a permanent regression. Keep this finding open until actual-model unseen requests demonstrate the intended distinctions.

2. **Give every payload an explicit origin.** Use typed references for host-captured literals, exact unquoted spans, a generated draft step, and a reviewed observation of a source field. A generated draft or existing field identifier must never silently become an exact-literal payload. Generation and copying need their own authorized dependencies and outcome checks; the current exact-form capability should decline them completely. A source span remains supporting evidence, not an independent proof that the user requested its literal insertion.

3. **Offer source references that the host can bind directly.** The current global target enum allows a label from an earlier clause even when the current clause contains only a pronoun. The model then fails the later host check. Supply bounded mention identifiers with source locations and candidate field identities, including explicit back-references. Retain ambiguity handling and the unique preceding-target rule. Do not repair this by accepting any field ID or treating an absent label as an implicit mention.

4. **Model constraints at their actual scope.** Leaving a field unchanged and prohibiting a particular value are different requirements. A field can be changed to an allowed value while respecting a forbidden-value constraint. Compile explicit constraints into predicates on the relevant operation or final state, and test them independently of the model's classification. Do not infer that an empty constraint list proves a prohibition was respected.

5. **Use compiler feedback for bounded recovery.** The current one-retry source-coverage correction recovered the omitted unchanged-field sentence in the known corpus. Preserve its exact token counting, cancellation checks, original task authority and complete second-pass validation. If feedback expands to reference or intent errors, distinguish those diagnostics, record each attempt, and measure the effect on false acceptance as well as completion. Extra attempts cannot substitute for a correct contract.

6. **Keep every effect visible to the oracle.** Check complete allowed operation vectors, including repeated actions, target, mode, exact bytes and order. In the real browser fixture, independently record the target and both field values after each input event. A correct final value and even a correct event count can hide an incorrect intermediate effect. Include mutation of fields that should remain unchanged and Unicode normalization in the oracle's rejection tests.

7. **Qualify before switching production.** Preserve the frozen candidate, first-run failures, incomplete infrastructure run and continuation as separate evidence. Any corpus used to revise the next candidate becomes regression data. Test fresh phrasing before adoption, then exercise the selected planner through the actual coordinator and browser/native adapters. Zero accepted incorrect plans in this corpus is a necessary gate; a small passing corpus does not establish general natural-language reliability, mobile transport, interruption recovery or release readiness.

The broader [repair TODO](../../../TODO.md) and [original audit](AUDIT.md) remain authoritative. These steps refine F02 and the qualification work; they do not replace the remaining product repairs.

## Payload-origin implementation and the routing failure

The host now has a typed whole-field copy operation. It resolves source bytes from the ordered observed state, binds source and destination identities and values, and requires dispatch evidence in addition to exact resulting values. Owned WebKit documents can supply an independent operation receipt after a lost callback. An adapter without that receipt can prove dispatch only from a successful call in the live task. Copy-source values and exact literals stay outside model context and raw journal records.

The first model composition nevertheless failed **5/20** initial cases. It invoked existing v2 first and considered the copy capability only after an unsupported result. For `Copy the "Origin" field into the "Destination" field.`, v2 accepted the literal `Origin`, so the copy interpreter never ran. This is an incorrect accepted plan in the baseline itself, independent of the earlier v6 failure. Preserving an existing planner as a baseline does not justify trusting its classification as an irreversible routing decision. See [all first-run results](field-copy-v7-results.json).

The opt-in v8 candidate therefore makes one whole-goal decision with tagged supplied-text and field-value payloads. It shares the strict decoder and execution contract; normal composition remains v2 pending qualification. The revised instructions address source labels, literal words, self-copy, and unsupported conditions. These instructions guide the model; they are not independent proofs of intent. The frozen comparison contains all 20 copy cases and 34 earlier regressions. A separate 20-case phrasing corpus and six controlled browser cases were frozen before their inference.

V8 then passed only **44/54** known cases and accepted five wrong plans. Three confuse a supplied literal label with a copied field value, one reverses a repeated copy, and one emits extra intermediate edits for quoted field names. The typed representation exposes these mistakes but does not prevent them. Keep the unseen corpus unrun while repairing the regression failures. One hypothesis to test separately is that replacing every quotation with a payload marker, then supplying label matches indirectly, loses useful target/value syntax. Preserve host ownership of exact bytes while testing a clearer reference representation; do not assume another instruction paragraph resolves the information loss. Complete command grammars may bind unambiguous requests directly, as the existing quoted `set` compiler already does, provided they consume the entire request and preserve every ordered operation. Broader English interpretation still needs independent qualification.

Follow these gates before adoption:

- [x] Compile copied data from host-owned observations and preserve ordered source dependencies.
- [x] Check retained source/destination identity and exact bytes immediately before owned-browser input.
- [x] Require independent dispatch receipts for recovered copy operations, including equal-value/no-op copies.
- [x] Test literal and copy origins separately even when they produce identical bytes.
- [ ] Pass the fixed complete-plan comparison without accepted wrong operations; retain all conservative failures too.
- [ ] Pass independent phrasing under unchanged source, model, sampling and expected outcomes.
- [ ] Execute the frozen visible browser cases through the actual runtime, coordinator and DOM adapter; verify typed origins, every intermediate full-form state and no replay.
- [ ] Extend dispatch/recovery qualification to ordinary text operations and native AX adapters; the copy receipt change alone does not close F26.
- [ ] Add generated drafts as an explicit capability with reviewed content and outcome predicates.
- [ ] Compile preservation, forbidden-value and conditional requirements at their actual scope before supporting them.
- [ ] Qualify external native targets, mobile-to-Mac transport, interruption points and supported hardware before a release claim.
