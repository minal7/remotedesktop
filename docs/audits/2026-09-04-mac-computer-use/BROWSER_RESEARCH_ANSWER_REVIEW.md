# Deliver research answers with their complete supporting evidence

Source checkpoint, 2026-09-08. Previous checkpoint: `8088624`. Execution remains deferred.

## First-principles defect

Finding a page is an intermediate action. The user asked for information meeting a complete set of conditions. The previous production research driver could read pages, follow links, retain earlier readings and return partial progress, but it had no terminal research-answer path. A model declining another link therefore left the request pending even when a complete informational answer was present on the current page.

The opposite shortcut would also be wrong: neither a successful page load nor an isolated price/count match proves that the request is answered. An answer must identify what it is reporting, retain the evidence and qualifications supporting that report, account for each original condition, and reach the user intact. A quoted stock number cannot erase a purchase cap; two cards need not represent two distinct concerts; replaying a prior answer is not a new availability check.

This repair introduces a limited source-reported informational answer. It does not establish independently verified availability, bookability, semantic truth or general browsing correctness.

## Source changes

1. [Answer admission](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchAnswer.swift) builds an eligibility set from the exact current native reading and original goal revision. It requires a permitted answer source, a complete requirement-mapped review, no unresolved source clause and no omitted page structure, embedded content, controls or projected records. Any page with controls is currently ineligible because the result-reading projection does not carry their selected values. This is deliberately restrictive pending control-aware answer evidence.
2. Every candidate must have a proposed single-offer association and complete projected text/link coverage. Every original requirement remains in the ledger. Missing, unsupported, contradictory, incompatible, ambiguous or unparsed conditions prevent eligibility. Supported scalar conditions retain their native literal comparisons. A positive requirement review is still a cited model interpretation.
3. Result-set counts are evaluated over the selected eligible candidate indices against the original compiled count/unit/comparator. Selections must use offered indices once each and an allowed count. Exact duplicate normalized complete passages cannot count twice. Different passages alone do not establish distinct offers; semantic deduplication remains the final selector's responsibility. There is no zero-result completion path or inference that a finite reading proves absence.
4. Proposed available capacity can satisfy the existing supported minimum comparison, but a simultaneous quantity field interpreted as a selected amount, purchase limit, package size or unknown meaning now prevents answer eligibility. Those meanings need joint interpretation before completing a ticket/party request. Conditions expressed outside quantity fields still require semantic review. This is not a general package/stock/price solver.
5. Only the exact whole prohibition clauses “do not/don't buy/book/purchase/reserve” can be treated as execution restrictions in this answer path. They stay in the original model context and delivered ledger. Other prohibitions, including excluded result categories or venues, remain unresolved. This exception does not independently prove the semantics or lack of side effects of every navigation; the existing native navigation policy/journals and selector restrictions still apply.
6. [Link planning](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserLinkPlanner.swift) can propose a closed `answer` array instead of a link or historical recall. The production decision input is version 6 and the local output schema is `browser_result_link_v3`. The prompt requires reconsidering the complete original request, accepted answers, all fields/qualifications, exclusions, quantities, distinctness and unresolved actions. The model proposes indices only; it cannot author answer prose or a URL. Legacy link-only inputs retain their previous contract. Pending navigation recovery remains link-only and cannot bypass a retained effect with an answer.
7. [The input/native binding](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResultCandidates.swift) includes the complete goal, reading, interpretation, review, eligible passages and source. A changed goal, reading, source, browser session or control state cannot reuse the prior selection. Native preparation revalidates the exact current page and answer-source policy before and after constructing the answer. Final synchronous checks bind delivery to the retained document/session/control state; they do not freeze the external website indefinitely.
8. [The retained owner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) keeps the previous common decision deadline and cancellation/join boundary across link selection, historical recall and answer selection. Answer preparation requires no outstanding question, edit or navigation stage. Pause still cancels ownership, clears current-page authority and requires explicit handback. A historical reading may inform selection but cannot supply a terminal candidate in this version.
9. [The production driver](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchDriver.swift) returns a typed research answer after native preparation. [Capability routing](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseCapabilityExecutor.swift) rejects plain `.completed` prose from a research delegate and validates typed answers through the retained owner. Default/injected planners without answer support retain their earlier link/progress behavior.
10. The delivered message quotes every line of each selected candidate's complete native passage, all surrounding page text and every original requirement source fragment. The exact observed HTTP(S) source URL must pass the existing reporting filter: no credentials, query or fragment and a bounded length. A query-bearing search URL cannot become a terminal answer source; a permitted detail page is needed. This filter is not proof of public access or permission to share all page content.
11. The terminal ledger retains only 4,000 Swift Characters; the wire allows 8,000. The builder rejects a complete message exceeding the smaller ledger limit or 16 KiB, rather than letting either layer truncate qualifications. It also rejects control characters other than newline/tab. Large source passages, context or requirement ledgers remain pending until a complete chunked/structured delivery format exists. Unicode byte length and Character count are checked separately.
12. [Host delivery](../../../host-mac/RemoteDesktopHost/ComputerUse/HostComputerUseManager.swift) rechecks the current owner and uses the existing durable first-result-wins terminal path, owner retirement and exact prompt replay. No phone protocol change is required; the existing client presents the response as literal text. Replaying a terminal answer performs no new search or inference and makes no new freshness claim.

No extra model worker or separate answer-generation call is introduced. The existing decision call gains an answer variant. This changes the prompt and schema and therefore requires model qualification; source construction alone says nothing about success rate, context fit on real pages, latency or fan load.
