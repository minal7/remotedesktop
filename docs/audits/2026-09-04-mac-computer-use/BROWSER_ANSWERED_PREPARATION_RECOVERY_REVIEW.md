# Keep earlier capture recovery reachable after an answer

Source checkpoint: 2026-09-09. Parent: `5c4fa7d`. Source repair and authored regressions only. Compilation, assertions, inference and live qualification remain paused.

## First-principles finding

Accepting an answer changes the retained conversation. Reviewing its form implications creates a new set of purposes. Neither fact establishes new field values or completes an input operation.

The owner installs a revised preparation before cancellable native work so the revision and its future callbacks cannot be lost. However, the new frame first needs the earlier frame's captured baseline. When an earlier retain-only criterion has changed, that baseline reconciliation can fail before the new frame starts its own field capture. A revised scope that permits an edit then hides the earlier retain-only recovery: the owner previously inspected only the current frame's scope.

Discarding the revised frame would lose its reviewed duties and scoped readings. Running its old edit plan to escape the failure would use stale premises. Relaxing every physical preparation would allow already captured input preconditions to be replaced. Recovery needs to reach the original capture only through revisions that have not started their own field, binding or preservation capture, and then require a fresh review.

## Source repair

[Preparation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormPreparation.swift) now distinguishes its own read-only recovery from inherited recovery. `hasStartedCapture` includes every field/binding/preservation capture's dispatch flag, stored field/evidence results, finished preservation and a prepared input. A physical revision can reach an eligible earlier frame only while all of these remain absent. Existing recorded callback attempts are not cleared, including failed or interrupted ones.

Inherited recovery retains the current frame. It restores that frame's reviewed page and scoped readings, invokes the earlier frame's recovery under the same ownership checks, resolves the sealed capture origin, restores the current frame again, and publishes the inherited origin only after current/cancellation checks. The earlier frame may complete its original retained callbacks; the skipped physical revision does not start its own capture or consume a form proposal.

The inherited record carries the actual historical capture, its own review context and its existing repair record. It does not create a replacement capture, input, receipt or criterion proof. A repeated identical record reports no progress. The existing per-frame recovery limit and revision-depth bound remain in force. Cancellation can leave a valid ancestor record retained while preventing publication to the current frame; handback can finish that propagation without replaying input.

[The owner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) requests a new preparation review when either local or inherited criteria recovery is pending. It does not reuse a cached action in either case. Resuming the skipped frame directly rejects before native work: its earlier edit scope cannot consume inherited recovery. A fresh reviewed revision can use the earlier capture while keeping the intervening frame and its semantic duties.

## Separate capture provenance from reviewed purposes

`captureOriginForRevision` walks only retained, unstarted revisions that hold inherited recovery. Each frame restores its original reviewed observation. It also compares its immutable scoped readings with the proposed revised page, preventing a newer review from silently substituting different observed values. The recursion verifies that the earlier origin still equals the retained inherited record.

A version-6 preparation baseline separates the capture's review context from the newer unexecuted review context. The former validates the historical capture's original goal and metadata; the latter supplies the newer field purposes to planner context. The current obligations context keeps all accepted preservation/read duties. Both historical contexts and the original captured fields remain validated against the new input. Earlier native desired values, input IDs, observation origins and actual-input sources remain in the original continuation.

The resolved origin is frozen beside the baseline before any later native field revision. Resuming after that revision starts does not rerun an earlier full-field preparation against the expanded adapter. Native revision still checks the original captured requirements and earlier native repair origins, then produces strict new input snapshots. No native command, query authority or proof format was added by this change.

Ordinary revisions keep their earlier digest versions when the capture and review contexts coincide. The added immutable scoped-reading comparison also applies to ordinary revision origin resolution; explicit supersession of those earlier observations is still not implemented.
