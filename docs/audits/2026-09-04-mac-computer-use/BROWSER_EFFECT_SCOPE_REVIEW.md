# Accounting for unread controls before dropdown effects

Source checkpoint following `379fe8d`. [Popup criterion preservation](BROWSER_POPUP_CRITERIA_REVIEW.md) protected criteria once observed, but an owner-only initial scope could omit a required date altogether. Normal research dropdown opening and option selection now require complete reported metadata plus explicit review of every remaining unread control. This is structural enforcement of a semantic review, not proof that a model interprets the task correctly. No build, typecheck or test execution has qualified this source.

Follow-up: [form/query scope review](BROWSER_FORM_EFFECT_SCOPE_REVIEW.md) now connects outside preservation and unconstrained query criteria to the normal research owner. Internal editable-form scope and universal effect/criterion enforcement remain open.

## First-principles failure

Preserving an observed baseline cannot protect a criterion that was never observed. Conversely, reading every field would collect unrelated private values without establishing relevance. The missing step is an explicit account of unread controls against the complete request: which could matter, which are unrelated based on visible metadata, and which remain unresolved.

The account must be complete relative to the reported page, bound to the original task and current native evidence, and unable to disappear during replanning. A partial review, a new snapshot or a repeated model call must not gain effect authority or restart the decision deadline. A visible selected value still does not establish provider acceptance, availability or correct results.

- [Explicit review parts](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserEffectControlReview.swift) account for exactly the next ordered controls. Each entry is `relevant`, `unrelated` or `unknown`, with bounded original requirement and observed-evidence references. Relevant/unrelated entries must cite their own control; another unread control cannot substitute as evidence. Unrelated requires complete reported metadata and no read requirement. Relevant requires an accepted outcome/condition reference. Missing, repeated, reordered, foreign, stale, boolean or fractional references fail decoding/retention. A review contains no newly read values.
- Each review part has at most four entries. The next part is sized using a conservative maximum canonical reply of 896 bytes, within the existing 2,048-byte/128-value action parser. Parts retain exact goal interpretation and page evidence. Only complete review in which all remaining unread controls are explicitly unrelated can expose normal popup/option actions. Relevant or unknown controls keep that gate closed.
- `extend_inspection` adds only newly offered relevant/unknown controls under motivating readable requirements, up to the existing sixteen-control total. It cannot drop, reassign or duplicate an old read, or read a control just reviewed as unrelated. Native observation revalidates the original scoped snapshot and native objects before reading the combined scope. A new scoped snapshot discards all prior unread-control review authority and requires fresh review of remaining unread controls. A visible listbox is separate metadata and must be explicitly accounted for; the production gate does not infer aliases from similar captions.
- [The research owner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) resolves review parts, recall and scope extensions within the original action deadline. Cancellation joins outstanding work; Pause/handback expires speculative scope/review authority while retaining the original task. - A completed structural review is bound into normal popup and option-selection intents, their payload fingerprints and version-3 effect contracts. The existing same-document retained-baseline guards can stop legitimate transitions until this mapping exists.
