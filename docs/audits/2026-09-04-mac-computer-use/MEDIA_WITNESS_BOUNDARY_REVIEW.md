The available codec hooks are candidates for carrying capture evidence, but a raw encoder-buffer/decoder-buffer hash is not a sufficient implementation contract. No production or test source changed in this checkpoint. Fresh-image recovery remains unfinished.

## Findings that change the implementation

**Submission is not output.** The [H.264 encoder reference](https://github.com/webrtc-sdk/webrtc/blob/30d5e63ae91da483e06577b5c35ee91cc5e5c3db/sdk/objc/components/video_codec/RTCVideoEncoderH264.mm) can return no output for repeated millisecond presentation times or a native session reset. It retains timestamp/rotation parameters for asynchronous output and may crop or convert input buffers. A requested keyframe is not confirmation of a delivered independent picture. Correlate the exact codec instance and request; never borrow the next image's metadata to replace a missing callback. An attachment on the original pixel buffer does not automatically survive every adaptation.

**Transport may change valid encoded bytes.** The [incoming depacketizer](https://github.com/webrtc-sdk/webrtc/blob/30d5e63ae91da483e06577b5c35ee91cc5e5c3db/modules/rtp_rtcp/source/video_rtp_depacketizer_h264.cc) can rewrite SPS video-usability information to reduce decoder delay and update aggregation lengths. It recognizes SEI units, making an in-band witness a candidate, but that does not prove preservation through the installed pipeline. A raw whole-buffer hash can consequently reject legitimate output. Omitting all parameters to make hashes match would discard information used to interpret the picture.

**Reconstruction changes framing and parameter placement.** The [SPS/PPS tracker](https://github.com/webrtc-sdk/webrtc/blob/30d5e63ae91da483e06577b5c35ee91cc5e5c3db/modules/video_coding/h264_sps_pps_tracker.cc) can prepend stored out-of-band parameter sets before an IDR and insert Annex-B start codes. It can drop malformed input or request a keyframe for missing dependencies. The [packetizer](https://github.com/webrtc-sdk/webrtc/blob/30d5e63ae91da483e06577b5c35ee91cc5e5c3db/modules/rtp_rtcp/source/rtp_format_h264.cc) splits and aggregates NAL units. A witness therefore needs a defined access-unit representation, including active parameter state and dependencies; packet offsets or assumed unchanged `Data` objects are insufficient.

**Decode admission is not a displayed image.** The [H.264 decoder reference](https://github.com/webrtc-sdk/webrtc/blob/30d5e63ae91da483e06577b5c35ee91cc5e5c3db/sdk/objc/components/video_codec/RTCVideoDecoderH264.mm) retains its callback and received RTP timestamp per asynchronous request. Failure can produce no image; native session reset can retry a request. Older work may retain an earlier callback. The received timestamp can correlate requests only within the exact decoder instance/generation, with bounded wrap/collision handling. It is not a cross-peer capture identifier. The [decoder adapter](https://github.com/webrtc-sdk/webrtc/blob/30d5e63ae91da483e06577b5c35ee91cc5e5c3db/sdk/objc/native/src/objc_video_decoder_factory.mm) reconstructs a frame with native timestamp milliseconds set to zero. Verified ownership must survive the actual output-buffer bridge into the renderer.

These are source observations and resulting design constraints, not executed behavior of the installed binary.

## Required integrated implementation

1. **Negotiate the implemented media path.** Bind capability to the actual selected codec and framing. Qualify H.264 explicitly and retain unsupported/unverified status for other paths. Renew the challenge for input scope, display, track/attachment and activity/reveal changes while preserving the independent paused AI task.
2. **Acquire source evidence.** Preserve the [fresh-capture requirements](CAPTURE_FRESH_IMAGE_DESIGN_REVIEW.md): exact owner/attempt/display, original recovery episode, request ID and native acquisition boundary. One real still operation remains charged across replacements until callback completion. Missing native evidence stays unavailable. Arrival time and still success cannot stand in for source timing or continuing-stream recovery.
3. **Bind the encoder input and output.** Carry an opaque source record through the admitted adaptation path. Reject a witness if that association is lost. Register bounded request correlation before native encode; retire it on failure/release/reconfiguration. Associate actual output with the original request, not merely with a timestamp observed later.
4. **Define canonical H.264 evidence before emitting it.** Include coded picture data, active SPS/PPS, relevant other units, order and an independent recovery point. Account explicitly for the observed rewrite and insertion behavior. Prefer matching normalization at sender/receiver boundaries using the same reviewed rules; the exact normalizer still needs inspection and implementation. Restoring original parameters instead would also require qualifying any decoder delay/buffering it reintroduces. Neither approach is implemented or qualified here. Do not hide hash mismatches by omitting parameter semantics.
5. **Bind the witness to the access unit.** Carry request/input/display/source identity and a nonwrapping source sequence with exact canonical evidence in the same media unit. Bound bytes, NAL count, parameter state and outstanding work before allocation. Reject malformed, duplicate, conflicting or mismatched evidence. Start recovery at a valid independent picture; preserve its verified dependency chain or demand another independent recovery point after loss/reset. A witnessed delta alone is insufficient.
6. **Join actual decoder output.** Register the accepted unit under its decoder instance/generation and received timestamp before admission. Require its matching output callback, rejecting ambiguity, duplicates, missing output and retired generations. Preserve the record through the actual output buffer, not a separate probe. Timeouts cannot claim that native work completed or released its resources.
7. **Present the exact image before enabling input.** Connect its verified record to the [surface driver](../../../ios/RemoteDesktop/Transport/RemoteVideoPresentationSurface.swift) and [presentation ledger](../../../ios/RemoteDesktop/Transport/RemoteVideoPresentationLedger.swift). Recheck current challenge, sequence, image, layout and successful drawable receipt. Prevent older queued media from replacing current verified output. Local redraw retains source identity; it cannot advance the source sequence or renew a challenge.
8. **Qualify the whole chain after permission.** Compile the actual wrappers/bridge and exercise raw/rewritten SPS, out-of-band parameters, aggregation/fragmentation, missing units, timestamp wrap, asynchronous failure/reset, queued old frames, stationary reveal, input cleanup and login handback. Then verify full travel/concert/movie tasks. Model selection/distillation and 8 GB/fan qualification remain unfinished requirements.

The immediate source step is a bounded canonical access-unit representation reviewed against the precise rewriting algorithm, followed by codec/request-owner integration. An isolated checksum helper or acknowledgement cannot close this requirement. Native capability qualification remains deferred.
