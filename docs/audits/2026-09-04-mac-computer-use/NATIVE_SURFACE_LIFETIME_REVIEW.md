# Isolating native surfaces between video attachments

Source review and repair, 2026-09-10. This follows [renderer attachment ownership](RENDERER_OWNERSHIP_REVIEW.md). No build, typecheck, XCTest/assertion execution, native rendering/capture, app launch, browser action or model inference ran. The installed app is unchanged.

## First-principles finding

Closing entry into a renderer does not cancel work already queued inside it. Reusing the same native view for another attachment lets old work write into the replacement's frame cache and drawable state. The previous repair gated the synchronous sink call but deliberately left this native object reuse open.

The inspected local LiveKit 144.7559.3 `RTCMTLVideoView.h` exposes renderer methods, size-change delegation and an enabled property; it does not expose a per-frame presentation receipt. The [M144 fork reference](https://github.com/webrtc-sdk/webrtc/blob/30d5e63ae91da483e06577b5c35ee91cc5e5c3db/sdk/objc/components/renderer/metal/RTCMTLVideoView.m) queues size updates onto the main queue, retains a frame for later drawing, and ignores nil frames. This reference explains the risk but still is not verified provenance for the installed binary. Hiding or removing a view also does not establish the exact instant at which the display compositor stops showing its old pixels.

Apple provides a lower-level [drawable presentation callback](https://developer.apple.com/documentation/metal/mtldrawable/addpresentedhandler(_:)). The inspected `MTLDrawable.h` describes a presentation callback and a `presentedTime` that is zero for unpresented/skipped frames. Using that evidence will require owning the exact drawable and mapping it to the exact decoded frame and current attachment/layout. The public WebRTC wrapper does not provide those identities. Neither a size callback nor a command-buffer completion can be substituted for that missing association.

## Source changes

1. **Separate the reusable surface owner from its native sink.** [RemoteVideoSurface](../../../ios/RemoteDesktop/Transport/RemoteVideoSurface.swift) prepares an explicit attachment. Each production preparation creates a new native view. The [binding](../../../ios/RemoteDesktop/Transport/RemoteVideoRendererBinding.swift), [transport interface](../../../ios/RemoteDesktop/Transport/Transport.swift) and [session/sidecar](../../../ios/RemoteDesktop/SessionModel.swift) retain the reusable owner, while the transport registration retains the attachment's native renderer and removal action. A raw cached native renderer is no longer the surface-binding interface.
2. **Reserve before creation and clean up exact objects.** `RemoteVideoSurfaceLifetime` reserves one identity before calling its factory. Active preparations cannot overlap. Creation failure clears only its reservation. Retirement removes ownership before invoking external cleanup. Creation or installation that returns after retirement is rejected and its exact old object is removed, even if a successor has already been installed. The removal action must be idempotent and act only on its argument. An attachment's cleanup is one-shot and can remove its sink after its container owner has deallocated.
3. **Give every attachment its own native child view.** [RemoteScreenView](../../../ios/RemoteDesktop/Session/RemoteScreenView.swift) now contains a stable `RemoteVideoSurfaceView`. It creates `MetalSafeRTCVideoView` only during attachment preparation, after checking Metal availability. Retirement hides and disables that child, then removes it from its superview. Delayed internal work can still change the removed old object; it no longer shares a native frame cache or drawable sizing object with the successor. No nil-frame clearing assumption is used.
4. **Keep layout metadata with the attachment.** The container lays out its current child using the immutable `DisplayInfo` captured for that attachment, including the full-display marker. Later container bounds changes recompute that child's rectangle from the same descriptor. A delayed SwiftUI display publication cannot replace the attachment's descriptor. The existing input geometry, cursor, zoom and logical full-display mapping remain in the outer screen view. This is source association, not proof of synchronized native presentation and input.
5. **Drain reentrant preparation before installing its successor.** [WebRTCTransport](../../../ios/RemoteDesktop/Transport/WebRTCTransport.swift) checks the exact surface owner, track, display and presentation lease after preparation. A stale prepared attachment is removed before another attempt. Native registration happens only after a current attachment exists. Retirement first closes/joins the synchronous subscription gate, retires the visible attachment, then removes that subscription from its retained original track. Failure to prepare a current surface ends that video transport instead of waiting indefinitely for impossible frame readiness; the sidecar's existing disconnect path preserves the independent TLS task channel.

The wire format is unchanged; the [protocol documentation](../../../protocol/PROTOCOL.md) records the stronger local ownership rule and the remaining presentation gap. The production factory always creates a new child. The generic factory contract requires a new sink; it does not inspect a renderer's private state or prove that a third-party factory never reuses one.

## Remaining work in order

1. **Add an actual presentation witness.** Own the decoded frame to drawable association and acknowledge a non-skipped native presentation under the exact attachment and layout. Reject queued old acknowledgements after retirement, layout/viewport changes, account shielding and activity loss. A newly allocated view plus a returned `renderFrame` call still does not establish displayed pixels. Private KVC access to the wrapper's internal Metal view is not a sound contract.
2. **Bind pixels to current source capture.** A new view can receive an old queued decode. Carry identity through adaptation, codec, media transport and rendering; do not use an independent metadata message or normalized packet timestamp as pixel proof. Preserve the [fresh-image design constraints](CAPTURE_FRESH_IMAGE_DESIGN_REVIEW.md).
3. **Qualify retirement and resource lifetime natively.** The current gate joins synchronous sink calls but cannot cancel their deferred internal work or retract committed GPU/compositor work. Check callback threading, native track add/remove, UIKit removal, pending size/frame delivery and deallocation. Retired native work may retain resources until it finishes; new-view allocation is not proof of bounded memory or thermal behavior. Failure within native renderer setup/drawing after construction remains unobserved by this preparation result.
4. **Recover stationary screens, foreground return and silent stalls.** These still require bounded requests, real-operation capacity accounting, qualified timing and explicit presentation rearming. Do not manufacture desktop motion to obtain a frame. Maintain capture and handshake deadlines.
5. **Verify input against visible current content.** Native zoom/rotation, full-display mapping, paused/removed surfaces, view replacement and held-control cleanup must be observed together. Current surface metadata cannot prove UIKit layout completion or which screen pixels the person saw when an input event was admitted.
6. **Finish real task and account-handoff qualification.** Keep the exact paused login task and explicit Resume controls across video failure. Verify current account/page state on resumption. The current TLS fixtures are idle ready channels, not live login tasks. The travel/concert/movie scenarios, alternative models or desktop training, and 8 GB/thermal qualification remain deferred under the user's restrictions.
