# Carry selected controls through browser research

Source checkpoint, 2026-09-08. Previous checkpoint: `244a944`. Execution remains deferred.

## First-principles defect

A list of possible dates or ticket types does not identify the current selection. A date input's original HTML attribute can also disagree with its current native value. Research previously discarded every control and marked every page containing one incomplete. That prevented false claims based on absent control evidence, but also prevented an otherwise complete research answer on ordinary pages containing a date picker or ticket selector.

Reading a value introduces a second obligation: keep its meaning and provenance. A selected count of two tickets is not evidence that two tickets remain. A current filter does not establish that the displayed results have refreshed to that filter. Native observation, semantic association, numerical comparison and task completion remain separate decisions.

## Source changes

- [Native observation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserDOM.swift) has an explicit research-only mode. It reads actual native date/time/month/week/datetime-local/number values, selected option identities, checked and indeterminate flags. It distinguishes action controls with no selected value from controls whose state is unavailable. General page, action and form metadata observations retain their previous mode.
- [Control-state records](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserControlState.swift) require an exact ordered binding to the native controls. The snapshot rejects missing paired observation metadata, mismatched records, invalid state kinds, foreign/repeated/reordered option IDs and multiple selections on a single-select control. State data contributes to the existing native byte bound. No observation or projection budget was enlarged.
- Whole-page authentication detection runs before state collection. The research reader excludes current text/search/email/tel/url/textarea values, disabled/read-only control values, and controls marked as credentials by the existing label/autocomplete guard. Unsupported or custom controls remain incomplete. Native submission names, option submission values and destinations stay outside the planner projection. This is a bounded collection rule, not a general guarantee that all page text or labels are free of personal data.
- [Owned-browser validation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseOwnedBrowser.swift) requires the returned observation mode to match the request. Later validation re-reads the same mode and compares the complete projection. Property-only changes to a date, selected option or checkbox invalidate a research reading even without a DOM mutation or input/change event. A fresh metadata snapshot cannot silently substitute for the retained research snapshot.
- Only the [research reading path](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) opts into these values. Native control objects and their full metadata remain retained with candidate and surrounding context. Historical reading recall retains the original observations; it cannot turn them into current-page action references.
- [Candidate proposals](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResultCandidates.swift) may cite offered control IDs in a separate `controls` array. Native admission checks visibility in the exact projection, candidate-subtree membership, source order, uniqueness and the existing total reference bounds. A title still needs ordinary text. Empty selections and mixed checkboxes stay in context but cannot supply a positive field value. Global controls remain surrounding evidence, not another candidate's field.
- [Result review](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResultReview.swift) retains complete field sources and permits citations of whole offered control observations. Native decoding refuses `availableQuantity` for any field sourced from controls, even if the model cites an inventory label. Selected quantities remain separate from stock, purchase limits and package sizes. Prompts require attention to all options, group labels, constraints and surrounding filters; their semantic application to an offer is still an interpretation.
- [Scalar assessment](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResultAssessment.swift) can compare a whole native ISO date value with an already compiled date requirement. It does not extract a convenient number from a longer option label. Raw numeric controls do not invent a ticket/party unit. A stock reading plus an unreconciled selected quantity still cannot complete an inventory request.
- [Answer rendering](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchAnswer.swift) keeps native control observations outside quoted page prose. It includes actual states, complete control/option/group labels, constraints and disabled/read-only/required/multiple flags. Checked and indeterminate are both preserved. Each reading's surrounding controls are included once, alongside its source and observation time. Eligibility and duplicate-passage identity include this context. Unknown or omitted controls and incomplete projections still block completion. Existing delivery limits reject an oversized complete answer instead of clipping qualifications.

The page projection uses version 4 for research state. When usable control references are offered, result extraction uses `browser_result_candidates_v2`, review uses `browser_result_review_v4`, and segmented review uses `browser_result_review_part_v3`. General metadata-only output remains supported. The model sees observations as untrusted data and cannot supply invented native values through these schemas. Actual model adherence and prompt/context fit remain unqualified.
