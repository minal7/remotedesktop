# Replacing a whole adult/child party

Source repair; execution pending. This extends [explicit scalar quantity corrections](BROWSER_QUANTITY_REPLACEMENT_REVIEW.md). No build, typecheck, assertion, browser, app, model, account-login or SSH execution occurred.

## First-principles finding

`2 adults and 1 child` and `3 adults and 0 children` both total three people, but they express different requirements. A useful correction flow must let the user change the breakdown. Checking only the total would hide insufficient adult capacity; retaining old browser fields solely because their numbers match would lose the connection to the corrected request.

The previous quantity replacement deliberately handled only a scalar count in the same unit. The existing native party compiler already grouped adult and child clauses across source rows, but its correction path could not retire that group as a whole. Final party reconciliation also treated every non-bound/non-confirmation group as unresolved, so simply adding supersession records would not have been sufficient.

The repair preserves one whole party origin, replaces both categories only after an explicit answer, and keeps the historical browser receipts separate from current field verification. Other parties, ticket counts, dates, prices and source restrictions remain independent obligations.

Omitted categories, totals, ticket counts, duplicate categories, conditional/negated text and extra instructions cannot complete the replacement. This uses the existing bounded party grammar, not unrestricted natural-language interpretation.

Known historical party clauses can survive source repartitioning or model relabeling. The new answer's complete source group supplies its party predicate; existing component-span logic supplies adult, child and derived-total normalizations. Successive corrections retain intermediate replacement links. Ordinary confirmation after correction remains a binding to the active party, not a new independent party.

Shared confirmations retain their separate origins. A clarification spanning two parties does not merge them into one replacement target. A conflicting answer about a result or ticket count also does not acquire party lineage; replacing a party cannot silently erase that unresolved answer.
