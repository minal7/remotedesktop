# Continue and query forms verified without input

Status: source integration through retained research stages, planner context, subsequent stages and explicit query preparation/navigation. Compilation, assertions, real native behavior and model qualification remain pending.

## First principles

A requested criterion can already be true before the application acts. Requiring an input receipt for every completed field confuses the requested outcome with an implementation action and creates unnecessary site events. However, treating that observation as an input receipt would hide uncertain history. The task therefore needs two facts: the latest verified criterion and the actual input history. Both must remain tied to original native controls and user source purposes.

The [preceding foundation](BROWSER_FORM_STATE_VERIFICATION_REVIEW.md) supplied a separate native observation proof. This repair connects it to the ordinary research form stage. It does not change generic literal typing or let matching values excuse an attempted disk operation.

## Execution and recovery

[ResearchFormStage](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormStage.swift) selects observation when every value in a reviewed proposal already matches its captured native value and no pending edit requires resumption. It still opens the original journal under an execution lease and validates contract identity. Before the first private verification it saves the planned contract, with no attempted/verified input status. Recovered planned state is confirmed for durability under the same lease, and exact journal state is confirmed again after native verification before completion is published. A concurrent journal change cannot be hidden by the value proof. A storage error cannot publish completion or allow a different proposal to reuse an empty stage store.

The stage retains the native callback capture and proof before later cancellable work, and always performs fresh proof validation before publishing its continuation. Pausing requires the existing explicit handback; a retained callback is historical, not current validity. Retrying a completed stage returns its historical receipt without retyping or re-observing. A later query still revalidates its live requirements.

If the original journal contains attempted, uncertain or verified input, the text engine performs its existing dispatch/outcome reconciliation. The observation branch does not rewrite that history or create a substitute receipt. A planned observation-stage journal binds identity only; completion and its native proof remain live-task state. This does not add process or document reconstruction.

## Criteria, actual edits and subsequent stages

The version-6 form continuation separately stores verified target IDs and source purposes, historically edited targets and source purposes, actual input IDs, and native state proofs keyed by criterion target. Observation stages add no input IDs. Their receipts report zero edits and a distinct verified-without-input count; stage completeness accounts for both kinds of verified work.

Later preparation borrows the same adapter and retains all prior criteria. Later actual edits keep observation proofs for other fields. A verified replacement edit removes the old proof for that target, updates its current source purposes and adds only its real input receipt. A later observation can likewise update the current criterion without claiming another edit. Incomplete suffixes retain their previous criteria and pending work. Changed unpreserved criteria become repair work whether they originated in an edit or an observation; changed controls cannot be matched to replacements by label.
