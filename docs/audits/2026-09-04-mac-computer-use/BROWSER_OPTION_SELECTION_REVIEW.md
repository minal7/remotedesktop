# Single-option selection: native foundation

Source checkpoint following `7077073`. This adds a private native adapter for a freshly observed, bounded combobox/listbox choice. It does **not** yet expose selection through the ordinary action planner, retained research owner or a journaled selection stage. The source is uncompiled and the prepared assertions have not run. No natural-language, provider, account or ticket workflow is qualified by this checkpoint.

## First-principles distinctions

An option is more than a caption: its group, qualifiers, order, availability, owning control and actual native objects determine what a click means. A focused option can differ from the selected option. The control's input or displayed text can differ from the application's accepted value. Even a correctly declared selection cannot establish that a provider accepted a code, refreshed results or returned matching inventory.

The [WAI-ARIA listbox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) distinguishes focus from selection and ordinarily uses one selection convention, `aria-selected` or `aria-checked`. When both attributes are used, their meanings differ. The new adapter therefore supports one consistent, Boolean convention across a complete single-selection list. It rejects mixed, missing, multiple, indeterminate or simultaneous conventions instead of treating them as interchangeable confirmation.

A second invariant is that choosing a ticket type must not silently change a date or another observed criterion. Preparation retains the actual states already admitted by the original observation scope. Confirmation compares those baselines before publishing a narrow selection receipt. This is evidence about observed states at particular boundaries, not proof of all website state throughout an arbitrary event handler.

Disabled, read-only, hidden, incomplete or ambiguous choices are unavailable. - [The existing composite reader](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserCompositeState.swift) now retains its list and ordered option objects privately beside its bounded graph. [The DOM adapter](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserDOM.swift) keeps this private data and actual observed states with its control bindings. The public page representation and action/page schema versions remain unchanged at 12/8.
- [The fixed selection script](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserOptionSelectionScript.swift) prepares a document/snapshot/control/option binding, then revalidates the full page before dispatch. The selected native option, owner, actual associated form, option/group meaning, referenced label objects and their ancestry must still match. Forms associated through an HTML `form` attribute are retained even when they are outside the control's subtree. A second discovered combobox owner of the same list is rejected at preparation. A scoped listbox view of the selected combobox's same native list is treated as an alias, rather than an independent criterion that must remain unselected.
- Other available observed control states are retained exactly, including metadata, actual form association, referenced objects and values. Stateless and unavailable controls are excluded. This does not expand the original text/composite read scope or inspect unscoped text values. The Swift adapter independently derives and verifies the ordered preserved-control IDs returned by native preparation.
- Native mutation pins cover required controls, list/option/group/label objects, associated forms and their ancestors. Removing a required subtree invalidates the plan, including removal followed by reinsertion of the same object. Confirmation also compares fresh graph meaning and native references, catching replacement, property changes and altered qualifications. A witnessed structural or preservation violation permanently withholds that operation's receipt; restoring the old value later does not erase the violation.
- Dispatch records the original operation in the native ledger **before** calling the captured synthetic-click primitive. An already-selected option produces an observation with `didDispatch: false`, without an event. Repeating the same operation acknowledges its historical attempt and does not click again; a consumed binding cannot run under a new operation ID. Unsent retirement tombstones the exact unattempted binding/operation. Attempted or uncertain work cannot be relabeled unsent.
- Confirmation has one two-second window starting at native dispatch; retries do not renew it. A changed trusted-input counter withholds a new receipt. Focus and display/input values may change independently of the selected flag, but cannot replace it. Busy state may remain pending inside the original window. The selected option's full meaning and every retained criterion must still match before a receipt is cached. Synchronous confirmation is captured before returning from native dispatch, so a later lost caller callback does not erase that historical observation.
- A receipt carries the original operation/binding/document/choice IDs, dispatch fact, complete resulting graph and preserved-control IDs. Swift validates its exact identity, selection convention, immutable graph meaning and readiness against the original intent. It carries neither a provider result claim nor a second event. Cached receipts are historical; they do not prove the current page remains selected or logged in. Authentication detected before an uncached confirmation stays a typed handoff error.
- [Owned-browser reply decoding](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseOwnedBrowser.swift) limits each new payload to its intended command and rejects unrelated page/form payloads. Adapter calls require the current document, presentation and source policy. Dispatch requires the caller's `willBeginEffect` boundary. The future journaled stage must persist the exact attempt there and join actual DOM completion before releasing its execution lease, including on cancellation, timeout and preflight failure. A required callback alone is not durable task execution.

Native plans and operations are each capped at 32 per document. Required object sets are bounded at 4,096 with ancestry depth 128; more than 512 delivered mutation records conservatively invalidate pending plans. Existing graph and page limits still apply. There is no inference or polling worker added by this source change.
