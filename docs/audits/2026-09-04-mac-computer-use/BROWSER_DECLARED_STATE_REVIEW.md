# Scoped website-declared control state

Source checkpoint on `codex/repair-natural-language-computer-use`, following `195a263`. Implementation and prepared verification only; native execution, model accuracy and provider behavior remain unqualified.

## First-principles defect

A research agent needs to distinguish what the page says, what a control reports, what an action changed and what a provider actually offers. None of those observations proves the others. The previous native-button path assigned a stateless observation even to an HTML button with `aria-pressed`, or with a checkbox role and `aria-checked`. A selected setting could therefore disappear from the result's qualifications. Non-native controls were omitted altogether, preventing useful observation of even a self-contained toggle.

ARIA defines checked states for checkbox/radio/switch roles, pressed states for toggle buttons and value attributes for slider/spinbutton roles. The permitted states differ by role. These are author-supplied accessibility semantics; collecting their attributes does not test the widget's implementation. [W3C WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria-1.2/).

## Source repair

- [DOM collection](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserDOM.swift) now represents six declared kinds: checkbox, radio, switch, toggle button, slider and spinbutton. This includes HTML buttons with supported declared roles or `aria-pressed`. Native input/select/textarea state retains its existing property-based path. Unsupported button roles no longer silently become ordinary stateless buttons. Unsupported interactive/composite roles and editable custom surfaces remain explicit omissions; structural roles such as heading are not mislabeled as omitted controls.
- [The existing scope decision](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserReadingScope.swift) offers supported declarations from metadata before reading their values. The original outcome/condition reference, bounded selection, full page validation and native-object checks still apply. No value from these controls enters general state observation. Recognized account/contact/payment/credential/birth-date fields stay excluded; the exclusion also checks the original `name` attribute when the declared control does not expose a form name. This remains a limited metadata classifier, not general private-field recognition.
- [Declared-state validation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserDeclaredState.swift) retains the complete supported state attribute set: `aria-checked` or `aria-pressed` for toggles, and every present `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-valuetext` for ranges. The object stays together rather than becoming one numeric substring. Missing, empty, oversized, malformed or unsupported states remain unavailable. Mixed is admitted only for checkbox/toggle-button declarations. Range reading requires a finite numeric current value and checks any supplied bounds. No implicit default, browser repair or inferred value is inserted. Each attribute is bounded to 512 UTF-8 bytes and the whole serialized state to 2,048 bytes; strict native JSON validation rejects duplicate or extra keys and non-string values.
- [Control state](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserControlState.swift) distinguishes `declared` from native scalar/text/selection/checked observations. Complete snapshots require exact scope membership for every declared value. Planner context includes `websiteDeclaredARIA` provenance and a `declared_attributes` object. Mixed observations remain visible as context but cannot supply a selected field value. Existing `controlState` provenance prevents these sources from supplying positive result support or exact offer prices. Answers retain the observation and its qualification; their headings now accommodate both native and declared controls.
- Revalidation checks the scoped attributes again alongside the existing complete page projection and native element identity. A host-only signature also retains role, name/autocomplete, labeling and relationship attributes so a changed `aria-controls`/`aria-owns` reference cannot silently reuse a reading. Replacement by an identical-looking element expires the evidence. This signature does not traverse an accessibility tree or collect owned options. Scope admission and collection remain one synchronous DOM invocation under the owner. Existing Pause, cancellation, manual login and explicit handback invalidate old authority and require a fresh scoped decision under the original task.
- Declared controls carry no form binding, native edit kind or query capability. Observation does not click them, type into them, change flags, apply filters or invoke form submission. Action context/schema advance to version 10 when scoped controls are offered. Page projection uses version 7 when declared-control metadata is present. Result and review prompts explain the new provenance without adding another inference stage; output review schemas are unchanged.

“Complete attributes” here means the supported state attributes above, not every accessibility attribute or all application state. Optional bounds/value text remain optional; the reader does not fabricate them. Disabled/read-only/required flags for custom controls report the collected declarations and do not prove effective interactivity. Literal declarations are useful evidence to inspect alongside independent result text, not a claim that a setting is rendered correctly or has refreshed the results.

## Prepared verification

Six new methods in [declared-state coverage](../../../host-mac/RemoteDesktopHostTests/ComputerUseBrowserDeclaredStateTests.swift) specify:

1. Custom and button-backed toggles/ranges are offered from metadata while general reading leaves their values unavailable and grants no form/query action.
2. Scoped readings retain exact attributes, provenance and scope membership; a forged snapshot without the scope is invalid, and mixed selections do not become scalar fields.
3. Missing/invalid toggle states, nonfinite/range-inconsistent values, duplicate keys, extra keys and wrong value types stay unavailable instead of receiving inferred defaults or repairs.
4. Account-labeled and account-named controls stay excluded by both proposed and native scopes. Unsupported dropdown/listbox/editable widgets remain omitted, while a heading alone does not create an omitted control.
5. Attribute changes, relationship changes, identical element replacement and a newly appearing password field invalidate an old scoped reading or require account handoff.
6. The research driver retains a declared toggle beside independent result facts without editing or opening its form. Control provenance cannot supply a result fact; Pause/handback reject the old scope while preserving the original task.
