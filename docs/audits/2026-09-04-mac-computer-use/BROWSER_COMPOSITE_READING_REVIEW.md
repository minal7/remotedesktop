# Scoped dropdown and listbox observations

Source checkpoint following `c32be39`. Implementation and prepared verification only; compilation, native execution, actual-model decisions and provider behavior remain unqualified.

## First-principles defects

Dropdown research involves several different observations: the typed input, the displayed value, the option list, declared selections and a keyboard-focus reference. Treating these as interchangeable can manufacture a selected airport, ticket type or quantity. Reading only a text input also loses the option's group and qualifications. Conversely, including option captions as ordinary page prose lets a choice such as “Two tickets USD 80 total” appear to be an independent result fact.

ARIA comboboxes connect an input/display element to a popup. Listboxes contain or own options, potentially through groups; active-descendant references describe focus separately from option selection. The reader uses those distinctions but retains literal observations rather than applying implicit defaults or certifying the widget implementation. [W3C WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria-1.2/).

The state includes owner/list declarations, list label and visibility/interactivity flags, every observed option with complete group labels and selected/checked declarations, and separate owner/list active-option references. Missing selected/checked declarations remain null, not inferred false. The references do not establish actual DOM focus, rendered highlighting or a selected value.
- Native combobox text uses the actual input property with separate `nativeInputProperty` provenance. Custom display text uses a bounded rendered-text pass that excludes its popup, hidden descendants and scripts. It does not use the label helper's overflow marker as a value. Typed or displayed text can differ from a declared selected option; all remain in the observation rather than silently choosing one as authoritative.
- IDs and relationship strings remain host-side; only retained native option IDs enter the observation. Referenced IDs must resolve uniquely in the same DOM tree. Duplicate visits, cycles, multiple explicit owners, conflicting physical group/list ancestry, foreign active descendants and unsupported nested interactive surfaces are rejected. Incomplete virtualized sets, inconsistent selection counts, invalid declarations and oversized graphs remain unavailable. A failed scoped graph also marks control coverage incomplete, so unread-control relevance cannot turn that failed collection into complete evidence.
- Graph traversal is bounded to 512 nodes, depth 32, 64 options and eight group levels. Labels are bounded to 256 UTF-8 bytes, input/display values to 2,048 and the complete graph to 8,192. ID indexing is bounded to 10,000 elements and 4,096 ownership references per tree. Existing sixteen-control scope, whole-page and planner projection bounds remain. Native validation rejects duplicate/extra keys, wrong types, foreign option references and native/display provenance mismatches. Oversized observations are not truncated into plausible partial selections.
- Revalidation reconstructs the graph under the same scoped reading. Stable native option IDs, retained list/group/label objects and ancestry references make identical-looking replacements expire the evidence. Changed selection, focus reference, input property, popup visibility or referenced label identity also changes the reading. Scope validation and collection still run synchronously inside the existing DOM invocation. The owner retains its cancellation/join and Pause/manual-login/explicit-handback boundaries; old scopes cannot resume after handback.
- Combobox/listbox/option contents are excluded from ordinary result-text collection. [Control-state provenance](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserControlState.swift) carries the full graph as a separate observation and still disallows positive offer support or exact offer prices from it. Answers retain whole control observations beside independent result prose. Planner/review guidance distinguishes declared selection, focus, typed text, groups, hidden/disabled options, busy lists and conflicting evidence. Action context/schema advance to version 11 when scoped controls are offered; composite page projection is version 8. No new inference stage is added.

This is observation, not popup interaction. It does not open, click, select, type, dispatch change events or submit a custom widget. Existing native text editing is preserved, but a typed autocomplete query is not proof that an option was selected. A list's complete currently observed DOM graph is not a provider's complete inventory or evidence that its results have refreshed. General private-field recognition and semantic relevance remain unqualified; known protected owner, popup or group metadata prevents reading that graph.
