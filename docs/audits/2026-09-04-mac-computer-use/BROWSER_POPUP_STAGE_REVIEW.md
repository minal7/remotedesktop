# Journaled dropdown opening foundation

Source checkpoint following `d75af73`. This adds the native adapter and one journaled opening stage. The research owner, action planner and driver do **not** offer or run this stage yet. It does not establish natural-language dropdown support, account continuity or provider compatibility. Compilation and runtime qualification remain deferred.

## First-principles defects

Reading a control does not authorize activating it. Opening a dropdown is an effect; selecting one of its options is another effect. A displayed list also does not prove which option is selected, whether its accepted value reached the application or whether results refreshed. Each transition needs its own bound target, durable attempt and independently observed postcondition.

A disk attempt proves that the host intended to dispatch. It cannot prove whether WebKit received the command. Repeating a click after a lost callback can close a dropdown or activate another handler. Conversely, permanently refusing an attempt that never reached WebKit strands recoverable work. Recovery needs the original immutable operation and native proof of whether dispatch began, under the same execution exclusion as normal work.

The chosen primitive is `HTMLElement.click()` in the existing isolated script world. HTML specifies that it fires a synthetic click with the not-trusted flag. It is not a physical pointer sequence and cannot qualify widgets that require trusted input or different events. [HTML activation behavior](https://html.spec.whatwg.org/multipage/interaction.html#dom-click). Arbitrary page handlers can still navigate, submit or perform other work; element metadata cannot prove their semantics. The foundation therefore remains unavailable to ordinary planner actions until the owner/driver integration and action-policy review are complete.

## Source changes

- [Popup intent and adapter](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserPopup.swift) retain the complete goal interpretation, original requirement index, exact page/document/context and observed combobox ID. Only an accepted research outcome/condition can propose opening. The requirement link is a proposal, not proof of semantic relevance. Descriptions hide the retained prompt/page. Preparation returns a private native binding and performs no activation.
- [The fixed DOM bridge](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserDOM.swift) admits a rendered, collapsed combobox with one uniquely resolved listbox relationship. A missing list is permitted for lazy creation; an existing list must be hidden and retain its native identity. Text/search inputs, explicit `type=button` buttons and supported custom elements can be considered. Submit/reset buttons, link ancestors, disabled/invalid disabled declarations, native popover/command invokers, nested text editors, conflicting references, visible/wrong-role lists and known protected metadata are refused. ID resolution is bounded to 10,000 nodes, ancestry to 128 and each document's plan/operation maps to 64.
- Dispatch revalidates the entire original page snapshot, native control/form identity, owner label references/ancestry and relationship signature. The native map records the operation before activation. A consumed plan cannot dispatch under a new ID; a repeated original ID returns its historical attempted status without another click. A changed or lost document cannot recreate this ledger from a journal status. Preparation is idempotent for an unchanged original binding.
- Confirmation observes the same owner expanded and its uniquely linked listbox rendered. An existing prepared popup cannot be replaced; a lazy popup is captured when it first appears. Changed owner identity, form, label, ancestry or relationship cannot become that receipt. A two-second native deadline starts at dispatch and does not restart on recovery. Observed trusted input since dispatch invalidates a new confirmation. This input counter is best-effort interference detection, not complete user-control attribution or a hostile-page proof. A retained confirmed receipt is an immutable historical opening fact; it is not a current selection, current page or research result.
- [The journaled stage](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserPopupStage.swift) compiles one operation from the original task/root goal, sequence and frozen target. The shared task engine persists an attempt before native dispatch. Recovery uses the same operation and binding: the native command can start it only when its ledger has no attempt and the original preconditions still hold. Otherwise it only acknowledges the prior attempt and queries its receipt. Cancellation, timeout and DOM failures join the underlying callback before releasing the execution lease. Typed authentication failures propagate through preflight instead of becoming a generic unavailable predicate.
- A proven-unsent native plan can be revoked and recorded as a durable retirement before a future target is chosen. Historical attempted/uncertain statuses are preserved in the tombstone. A dispatched or verified operation cannot be retired as unsent. Journal replacement failure poisons that store; recovery needs a fresh store/stage with the exact same frozen target, sequence and operation identity. The visible replacement is reconfirmed durably under the new execution lease before recovery proceeds. Parent-owned reopening and retirement publication are still future integration work.
- [Owned-browser reply validation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseOwnedBrowser.swift) admits binding/receipt payloads only for their matching commands and rejects unrelated page/form data. Existing task ownership, presentation, source-document and DOM completion checks apply. Root replacement clears popup records along with the other document-bound ledgers. No model schema or prompt changes in this checkpoint: action/page versions remain 11/8.

The stage holds callback completion through execution/retirement, but it does not yet own the research task's pending-operation slot. Direct internal adapter calls require a journaling callback; that convention is not a substitute for connecting the stage to the research owner. Starting a new stage while an old native attempt is uncertain must remain prohibited in that integration. There is no popup-specific navigation fence in this checkpoint. Popup/group semantics, changes outside the target and side effects from page handlers remain unresolved; the receipt makes only the narrow opening observation above.

## Prepared verification

Nine methods in [popup coverage](../../../host-mac/RemoteDesktopHostTests/ComputerUseBrowserPopupTests.swift) specify:

1. Read-only/idempotent preparation, original requirement binding, private descriptions and rejection of an array coercible to a valid operation ID.
2. Durable attempted state before activation, immutable receipt identity and no second click through repeated stage runs, repeated native calls or another operation on the same binding.
3. Cancellation after journaling but before native dispatch, followed by continuation of the exact original operation without running the normal dispatch hook again.
4. Unconfirmed and late page changes cannot replay the click, restart the native confirmation window or retire a dispatched operation as unsent.
5. Identical control replacement before dispatch requires native revocation and durable retirement, preserving uncertain disk history before a fresh target/sequence opens.
6. Submit/link targets, visible or ambiguous lists, wrong roles, protected metadata, disabled declarations and native popover activation are not prepared.
7. Popup replacement, changed owner relationship/label/ancestry and newly displayed authentication cannot become an opening receipt or authorize a second click.
8. Failure after journal replacement performs no click; a fresh store reconfirms and continues the same operation rather than creating a new identity.
9. Authentication before preflight remains a typed login requirement and creates neither an attempt nor a receipt.

These are controlled native/HTTP fixtures with explicit intents, not model or ordinary research-driver tests. Actual user input, callback cancellation/lease timing, production window behavior and real-site handlers remain unqualified.
