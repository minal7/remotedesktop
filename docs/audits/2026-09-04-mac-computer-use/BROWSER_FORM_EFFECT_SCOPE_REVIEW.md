# Review form and query scope before discovery or navigation

Source checkpoint following `15ceadf`. The [dropdown scope repair](BROWSER_EFFECT_SCOPE_REVIEW.md) did not prevent a form selection from omitting an outside preservation requirement, or a query from relying on an unconstrained field. The normal research owner now retains these selections for metadata review before releasing private form discovery or query navigation. This is source implementation and prepared coverage, not runtime or model qualification.

## First-principles findings

Choosing a form, observing its fields, deciding edits and submitting a query are separate obligations. Native form ownership determines which controls belong together; it does not prove that every field should be read, that a required outside field may change, or that the form's current settings satisfy the request.

A verified edit covers only the criteria in its retained contract. An unedited City field can still constrain a search even if Query was filled correctly. Calling City unrelated to avoid the gate is not a repair. Reading it may resolve its current value, but that new value must return to the planner for an explicit query decision. A cancellation/retry must keep that original reviewed value instead of adopting whatever is present after handback.

This checkpoint closes the outside-form omission and unconstrained-query paths in normal research. Supported editable members of the selected form are still delegated to the existing form planner/discovery. Complete per-field read necessity and preservation accounting **inside** that selected editable set remain separate unfinished work; this source does not claim universal scope correctness.

## Source implementation

- [Retained form/query scope](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserFormEffectScope.swift) binds the selected form or exact verified query receipt/submitter to the current goal interpretation and native page. Selecting a form/query is initially a proposal to review scope. It performs no field discovery or navigation. Earlier same-form preservation is included automatically; another form selection cannot drop already retained preservation or reassign its motivating reference.
- [Version-16 action context](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserActionPlanner.swift) reuses complete reported-metadata checks and ordered review parts. For forms, coverage consists of supported editable form members, stateless form buttons and explicitly preserved fields. Unsupported/read-only members and outside controls must still be accounted for. Missing metadata stays unresolved. The selected form's editable members remain subject to the separate form planner, native representation, private-value and field-count checks.
- For queries, coverage initially consists only of the selected submitter and current controls represented in the retained chain's required final values. Merely having discovered another field during an earlier form stage does not cover it. Its metadata needs explicit relevant/unrelated/unknown review. Visible unconstrained fields that could contribute a value to this chosen query cannot be classified unrelated: they need a justified reading or a retained verified obligation. Other unchosen submit buttons are not submitted by the existing native GET serializer and do not receive this value requirement. A relevant readable setting can enter an additive `extend_inspection` under an outcome/condition reference. Unsupported or unavailable required readings cannot release a query.
- `preserve_controls` adds an offered relevant/unknown supported field to the retained form preservation scope. It cannot duplicate, drop, reassign or collect a field reviewed as unrelated. It preserves the existing sixteen-field bound. The form preservation policy already admits explicit outcome/condition/prohibition sources; a negative user preservation clause can justify its existing private native read. This does not make arbitrary prohibitions or private account fields semantically appropriate reads. Query value reading still requires its stricter readable outcome/condition policy.
- [Review authority](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserEffectControlReview.swift) now also binds the selected scope digest, covered control IDs and read requirement mapping. Changing a form target, preservation scope, covered query criteria or native snapshot invalidates earlier parts even if some remaining control IDs overlap. Scope extension starts fresh review of remaining controls. All parts, selection changes, recall and native reads share the original action deadline.
- [The owner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) releases the exact retained form selection after complete review. A query that needed new value readings must return to the planner for a final explicit query decision on that scoped evidence; it is not automatically submitted when the read finishes. The planner can decline or select a justified form repair. Repeated/cyclic unresolved form selections reject instead of spinning until the deadline. Internal preservation proposals cannot escape as driver actions.
- Normal `prepareFormInput(for:)` and `openFormQuery(for:)` require completed review of their exact selected capability. The [form input](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormInput.swift) retains it through initial discovery and same-form extension. Version 10 adds a model-visible reviewed-scope flag without private proof identifiers. [Form contract identity](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserFormProposal.swift) includes the completed review digest; different citations change the contract even when the native fields, values and model-visible form context match. Legacy direct component APIs without a review retain their earlier context/identity path; the normal driver always uses the reviewed owner path.
- [Query navigation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormNavigation.swift) retains the completed review and binds its digest into the version-3 query operation identity, which participates in durable navigation binding. A failed/cancelled preparation keeps that exact intent. An unsent refresh restores only its original explicit value-reading scope, compares the full page while ignoring only the existing observation nonce/viewport exception, and compares original criterion fingerprints. A changed value cannot become the new query baseline. Existing native required-value/input-receipt checks, GET signature checks, store reconciliation and callback joining remain in place.
- Pause/handback invalidates speculative action review. Pending query preparation instead retains its original review and operation for reconciliation. Authentication uses the existing typed visible-handoff boundary. No password or account login is requested through the model's task-question channel.
