# Native Mac model candidates — September 14, 2026

UI-TARS-1.5-7B is worth comparing with Holo. Its small quantized package loaded locally and produced a plausible document-focus action. Neither this single proposal nor the research establishes that it is a better Mac task agent. Fara remains selected for browser work; Holo remains the native candidate, with UI-TARS experimental. No default or automatic routing change was made.

The user requested experiments, not an automatic replacement. The relevant target is complete Mac tasks within 12 GB total RAM, including accurate typing, verification, interruption and login handoff. A grounding score alone cannot establish those capabilities.

Holo3.1-4B advertises desktop, web and mobile use. That is evidence of intended desktop support, not demonstrated Mac specialization. Keep its retained successes and failures; do not transfer claims about larger Holo variants to this Q4 4B package. [Holo card](https://huggingface.co/Hcompany/Holo-3.1-4B), [release](https://hcompany.ai/holo3.1).

The UI-TARS experiment uses `UI-TARS-1.5-7B.i1-IQ3_XXS.gguf` from [pinned imatrix conversion 3c672f1](https://huggingface.co/mradermacher/UI-TARS-1.5-7B-i1-GGUF/tree/3c672f1bb1d0d6dc571e9a88d8174868487c21dc) and `UI-TARS-1.5-7B.mmproj-Q8_0.gguf` from [pinned static conversion 47441b8](https://huggingface.co/mradermacher/UI-TARS-1.5-7B-GGUF/tree/47441b8080b9848dac66f8a068f5e8d75c42739b). Both local files match their published byte counts and SHA-256 values. Together they occupy 3,970,645,216 bytes, approximately 3.70 GiB. These are file sizes, not runtime RAM.

One retained real TextEdit screenshot and the original editing goal were passed through the author's saved 1.5 prompt, with no previous actions and no tool execution. Only the sample task was replaced; its Chinese-thought instruction remained. The later `COMPUTER_USE_DOUBAO` template was not used. UI-TARS uses absolute coordinates in the processor-resized image, unlike Holo's normalized coordinates. Its trailing-newline typing convention also needs a deliberate adapter. [Saved request](https://github.com/bytedance/UI-TARS/blob/582f3a7ea5d285ee8ed9e2e84048d1ab01453c49/data/test_messages_single_image.json), [coordinate guide](https://github.com/bytedance/UI-TARS/blob/582f3a7ea5d285ee8ed9e2e84048d1ab01453c49/README_coordinates.md), [typing parser](https://github.com/bytedance/UI-TARS/blob/582f3a7ea5d285ee8ed9e2e84048d1ab01453c49/codes/ui_tars/action_parser.py#L403-L422).

Measured locally: startup 1.80 seconds, generation 10.39 seconds, total including cleanup 12.32 seconds. The response ended normally after 70 tokens and proposed `click(start_box='(231,107)')`. Its location is plausible within the document under the derived 1344×868 preprocessing dimensions; those dimensions were not printed by this quiet worker and require verification before enabling input. Peak sampled worker memory was 5,137,711,104 bytes, or 4.785 GiB. The worker exited normally and its credential was removed. This passes one compatibility probe under the diagnostic 5 GiB cap; it exceeds the unchanged production 4 GiB cap and does not qualify whole-app 12 GB usage or heat. Low-bit accuracy, history growth and complete tasks remain unmeasured. [Exact probe evidence](ui-tars-mac-probe-results.json).

The real TextEdit Holo baseline is still failing. Scripted exact Unicode editing, Save approval and replay rejection pass. A red native test exposed label-dependent geometry lookup; that shared defect is repaired. Holo's repeat still encounters pointer pixel changes and then incorrectly inserts the replacement at the existing caret after a rejected click. It never saves. This is not a clean model-only benchmark. [Eight retained attempts](native-real-textedit-results.json).

Follow the single [repair tracker](../../../TODO.md) rather than treating this research note as another status list:

1. Reproduce the remaining native pointer pixel mismatch with before/after region evidence. Test background changes, caret blinking and meaningful target changes separately; keep rejection for changed targets.
2. Require the same complete native task oracles for each candidate: real document edit/save, reading after scrolling, multi-field forms and cross-app transfer. Record incorrect recovery and false completion separately from adapter rejection.
3. Before enabling UI-TARS actions, verify actual preprocessing dimensions and implement only its necessary protocol translations, with explicit typing/submission and Mac modifier semantics.
4. Compare task success, repeated-run consistency, active time, interruptions and peak total memory. Keep login handoff and Stop/Resume in the acceptance set.
5. Select a replacement only after it improves those results within the 12 GB target. Do not add another browser route without a specific Fara capability gap. Do not begin distillation or pruning merely because a shared execution bug blocks both models.
