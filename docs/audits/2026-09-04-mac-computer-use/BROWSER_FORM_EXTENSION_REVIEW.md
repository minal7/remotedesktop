# Retained dependent fields and combined form verification

Source repair after `0802788`. Implementation and verification here are source-only. The [working TODO](../../../TODO.md) remains open; this is not real-site or model qualification.

## First-principles problem

Entering one search criterion can reveal the next control. A country or category selection may create a city field, change a placeholder’s type, or replace its options. Observing that change is necessary to continue the original task. Starting field discovery again would erase the native receipt proving the first input happened. Rejecting every new field would prevent ordinary multi-step forms from working.

The other half of the problem is verification: a successful city edit does not prove the earlier category is still selected, and it cannot replace the receipt for that earlier input. Each stage needs its own immutable contract and journal. A later query needs the accumulated criteria and all original input receipts, with current native checks. Explicit preservation must carry through every stage. When a later proposed edit intentionally revises one previously edited field, only that field’s expected value may change.

## Implementation

1. **Extend the native catalogue atomically.** [The DOM adapter](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserDOM.swift) adds `extendFormFields` under the existing exact page, native-object and authentication validation. It requires the same actual retained form, earlier required values and their dispatched native receipts. It enumerates the selected form plus newly requested and previously required outside preservation objects. Unchanged objects retain their IDs. A changed or replaced *unconstrained* placeholder receives a fresh ID. Earlier required objects cannot be rebound by matching labels, positions or values.
2. **Commit only complete discovery.** Candidate fields are assembled and checked against all existing label, visibility, shape, count and byte bounds before replacing the active catalogue. Failure leaves the prior catalogue and operation receipts intact, apart from invalidations caused by actual page changes. Successful extension never clears input operations. A retry after cancellation or a lost callback can reuse the catalogue that WebKit already committed; no input is dispatched by extension.
3. **Adopt a complete host mapping.** The text adapter decodes replies into a separate mapping, verifies every earlier required target still has its original native ID, then adopts the complete new field set. This also removes partial mutation during ordinary discovery reply decoding. Binding remains through native object identity. Old unneeded placeholder bindings may retire without retiring required input authority.
4. **Retain combined requirements.** [Form stage execution](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormStage.swift) now creates a private `ComputerUseBrowserResearchFormContinuation` only after the stage’s engine run and final checks succeed. It retains the same root, goal revision, document, form, ordered stage IDs, all original operation IDs, current expected values, explicit preservation references and motivating source indices. A dependent contract’s identity includes its predecessor digest. The accumulated continuation is historical requirements, never a current-value assertion.
5. **Carry earlier criteria into the next contract.** [Form input](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormInput.swift) version 5 validates the predecessor against current native field evidence, automatically carries explicit preservation, and exposes only previous edited aliases and requirement indices to the model. Private values and native receipt IDs remain host-side. [Proposal compilation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserFormProposal.swift) makes earlier criteria that are not explicitly edited into unchanged-value predicates for the next stage. An intentional later edit supersedes only its own field. Explicitly preserved fields remain uneditable. The [planner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserFormPlanner.swift) uses schema `browser_form_plan_v4` and explains the distinction.
6. **Connect the default owner path.** [Research task preparation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) replaces the broad automatic second-stage guard with same-form extension. It never falls back to new discovery on extension failure. The retained stage keeps the owner occupied until an outstanding DOM call finishes or the browser is released. Per-stage CAS journals, stable operation IDs and Pause/Resume recovery remain unchanged. A stage exceeding the cumulative receipt capacity declines before another stage journal or input begins.
7. **Verify the combined form before querying.** The [action selector](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserActionPlanner.swift) sees the accumulated edited criteria, not just the latest stage’s edits. Native query preparation requires every accumulated expected value and every retained input receipt. Earlier edited criteria remain required submitted members even when a later contract carries them as unchanged values. The cumulative query receipt bound is 64, matching the existing native operation ledger; the per-stage input bound remains eight and the parent stage bound remains 32. Values and fields retain their existing bounds.

The sealed combined predecessor participates in immutable input comparisons. The original single-text-task query API remains available. No replacement model, extra model worker, inference or GPU job was started.

## Limits that remain

- Extension requires the same interpreted goal revision, same native document and same selected form. Clarification answers after input, changed native documents after login, and transitions to another form need a broader reconciliation/replanning path. They do not inherit old field authority merely because the root request is still present.
- A website that resets an earlier criterion or replaces an earlier required object is still unresolved. The current stage cannot silently accept that reset or declare the criterion obsolete. Implement explicit revision of outstanding outcomes and native targets under the whole goal, preserving history and unresolved attempts. Automatic updates to unconstrained placeholders are handled; this does not cover every dynamic form.
- Source-bound proposals do not prove correct semantic choices. The model must still choose the right form, criterion, preservation reference, timing and intentional revision. The new prompts have not been run. A controlled mock choosing Category then City is not evidence that a lightweight model will do so on a real travel site.
- Native GET preparation still does not implement custom widgets, calendar/autocomplete flows, POST or script-based submission, embedded documents or arbitrary clicks. Required fields outside current projection/type/visibility bounds cannot be silently assumed satisfied.
- The parent research graph and native continuation are retained in memory. Per-stage journals alone do not reconstruct them after process/browser loss. Complete durable parent recovery and historical evidence retention remain open.
- A completed form or query is not a completed research task. Offer association, availability, quantities, distinct result counts, fees, ranking, public source links and complete answer assembly still need repair and qualification.
