## First-principles findings

Rejecting input in the transport is insufficient if the interface still appears interactive. A person can type into a discarded stream, leave a soft modifier latched, or finish a drag whose start belonged to the previous input lifetime. A connection-wide first-frame boolean also outlives the screen evidence that originally set it.

The [ordinary session model](../../../ios/RemoteDesktop/SessionModel.swift) previously reported an interactive remote screen whenever account revalidation was not pending. Its hello callback accepted only the initial connection, and display/frame callbacks were not all scoped to the exact transport. The visual sidecar retained its hello/display/frame flags during transient ICE recovery. The [screen view](../../../ios/RemoteDesktop/Session/RemoteScreenView.swift) kept touch, button, scroll and pointer-deduplication state, while keyboard callbacks selected current session/modifier state after an extra actor task.

A frame callback and fresh host pixels are different claims. A callback observed after a handshake can still describe video buffered before that handshake. This repair establishes callback and display-message ownership; it does not establish capture-time freshness.

## Repair

The Mac's [display encoder](../../../host-mac/RemoteDesktopHost/WireFormat.swift) now carries the current input acknowledgement with the dimensions, and the [peer session](../../../host-mac/RemoteDesktopHost/HostPeerSession.swift) supplies that exact acknowledgement. The [phone decoder](../../../ios/RemoteDesktop/Protocol/WireFormat.swift) retains it and rejects malformed metadata. For scoped input, the [native transport](../../../ios/RemoteDesktop/Transport/WebRTCTransport.swift) accepts display messages only for the presented acknowledgement. Legacy display metadata remains absent on the initial legacy path.

Each accepted new handshake creates a local presentation identity and installs a new frame probe. A callback must match the current input presentation, installed probe and video track when it reaches MainActor. Invalidating the presentation or replacing the probe rejects already-queued callbacks. The [presentation state](../../../ios/RemoteDesktop/Transport/Transport.swift) is separate from packet admission. Duplicate acknowledgement does not restart presentation readiness, and no probe is armed before the current handshake. This is observation after the handshake, not proof of capture after it.

The transport publishes input unavailability before recovery presentation. Both ordinary remote control and the sidecar clear old hello/display/frame evidence. Ordinary interactivity now requires current hello, valid dimensions and a subsequent frame. The sidecar accepts neither display nor frame readiness before its current hello. Its failure/recovery does not replace, stop or reroute the authenticated TLS prompt session. Native AI Resume and account-login verification remain separate handoff decisions.

The model clears local soft modifiers without sending releases into a replacement lifetime and changes a local `remoteInputGeneration`. Direct input requires an interactive screen and, when supplied by a bound capture, that same generation. The [modifier bar](../../../ios/RemoteDesktop/Session/ModifierBar.swift) captures its rendered generation and replaces its button subtree on generation change, so a late old button action cannot latch a modifier in the new session. Initial connection, recovery, account end, reset and transport replacement retire old local state. Ordinary callbacks and late connection failures check the exact current transport; recovery does not restart the prompt model as though it were a new connection.

The screen view checks availability and generation both on binding and at input entry points. It discards active touch/drag/button state, scroll ownership and pointer deduplication, resets remote recognizers and leaves viewport movement local. Scroll continuation requires the generation that began it; indirect movement cannot create a new held click from an old move callback. Long press requires a current tracked touch. Cleanup after a generation change produces no remote release events.

The [keyboard capture](../../../ios/RemoteDesktop/Session/KeyboardCapture.swift) binds hardware callbacks to both the input generation and one registration. A superseded coordinator cannot clear a successor's handler. It explicitly uses GameController's documented main handler queue and forwards without an additional task per key. `GCDevice.h` documents that queue; `GCKeyboardInput.h` documents current key state and `isAnyKeyPressed`. A held keyboard at binding stays suppressed through its final release before new input may be forwarded. Device behavior, callback order and sampling remain unqualified.

Text fields retain their input generation. Old typing and delete callbacks are rejected even after a replacement session becomes interactive; an explicit UI rebind resigns the old responder, clears marked/buffered text while input is fenced, then adopts the new generation. Both the [ordinary session interface](../../../ios/RemoteDesktop/Session/SessionView.swift) and [Computer Use interface](../../../ios/RemoteDesktop/ComputerUse/ComputerUseView.swift) close the remote keyboard on generation change. Ordinary remote control hides stale pixels with a restoration message, disables its input dock and keeps connection controls visible.
