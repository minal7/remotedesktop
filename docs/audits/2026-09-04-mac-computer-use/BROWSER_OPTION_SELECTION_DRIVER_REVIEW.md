# Option inspection and selection in retained browser research

Source checkpoint following `95b896b`. The [journaled selection stage](BROWSER_OPTION_SELECTION_STAGE_REVIEW.md) is now connected to the ordinary action planner, research owner and driver. The source has not been typechecked, built or executed. This checkpoint does not qualify model decisions, account login, provider behavior or whole-task completion.

## First-principles repair

A model cannot choose a ticket type from metadata that omits the actual options. Reading those options must also be distinguishable from reading results: sending the reading straight to the result assessor prevents the action planner from using it. The host now offers an explicit scoped inspection, returns the complete supported graph to the same action decision, and offers only choices that the native adapter can currently bind.

An option decision is a task operation, not a disposable click. The owner retains its original target, goal, observed criteria and journal through cancellation or failed storage. No new decision may replace an unresolved attempt. Even a proven-unsent retirement releases only that attempt; it does not authorize adopting a changed date as a new baseline.

## Implemented source path

- [The action input and decoder](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserActionPlanner.swift) add `inspect_options` and `select_option`. Inspection requires at least one offered composite owner, at most sixteen unique readable controls and accepted original requirement references. A selection must name an offered owner/option pair and an accepted requirement. Unknown IDs, extra keys, boolean requirement indices, prohibited requirements and a second inspection in the same decision are rejected. Neither action accepts arbitrary text, coordinates or a URL.
- Before inspection, the planner receives control metadata. [The explicit reading adapter](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserReadingScope.swift) revalidates the page and reads the selected scope. The next action input carries the whole supported option graph, including owner/list labels, option/group qualifications, disabled/hidden declarations and distinct selected/checked, focus and input/display observations. An oversized graph is not reduced to misleading caption fragments. The existing complete-context limit can reject an oversized decision.
- [Native candidate discovery](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserOptionSelectionScript.swift) shares eligibility checks with selection preparation and allocates no executable binding or operation. It returns eligible IDs under the current scoped snapshot, bounded to 128 options across the scope. [The host adapter](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserOptionSelection.swift) validates unique owners, complete scoped graphs and visible/enabled option membership before exposing those IDs. Preparation and dispatch still revalidate the original native objects.
- [The research owner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) resolves inspection and existing evidence recall inside the original action decision's shared thirty-second deadline. It checks ownership, goal revision, archive and current page at the boundaries. Inspection does not reset the deadline. If the final proposal is plain `read_results`, the owner revalidates and reuses the explicit scope instead of losing the values that were just read. Existing `read_results` with `read_controls` retains its previous result-reading route.
- The owner retains one pending selection stage, with at most 32 stage identities per task and journals under `Research/OptionSelections`. Other planning, observations, actions, questions and interpretation changes remain excluded until it reconciles. [The driver](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchDriver.swift) reconciles a pending selection before requesting another decision, then returns to fresh application/result evidence. Native uncertainty produces an intervention state with the original request still pending; a click is not reported as a completed research task.
- Failed stores reopen the exact original target, sequence and operation through the existing journaled stage. The owner records a selected/no-event outcome only after stage completion, and an unsent outcome only after native no-attempt proof and acknowledged durable retirement. Cancellation joins pending DOM callbacks before the owner operation returns. Stop retires the owner; it cannot authorize replay. Child journal durability and parent in-memory progress remain distinct.
- [Historical selection records](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserOptionSelectionStage.swift) retain original requirement source, complete option qualifications, dispatch/no-event status and original observed criteria. They are marked historical and reach later action context without native binding IDs, operation IDs, raw form destinations or option submission values. Current control IDs are attached only for the same document and a currently projected control. History is not provider inventory or proof that a setting is still applied.
- Before preparing a replacement selection, the owner checks every retired-unsent record in the suffix after the latest selected record. Its preserved controls must still be observable in the same document under the continuing original goal, and their complete baseline fingerprints must match. Missing, changed or unavailable criteria invalidate the proposal before a new binding is allocated. This closes baseline replacement during this selection-recovery chain; it is not yet a shared invariant across all browser actions.
- Authentication remains a typed host handoff boundary. A login page cannot prepare a selection. Pause/manual control expires speculative proposals and explicit handback refreshes the browser context; an already-pending stage must reconcile its original operation. Prepared coverage exercises these source paths, but does not demonstrate a visible provider login or authenticated host/phone composition.
- Action context/schema version 13 is used when option inspection, an inspected scope or selection history is present. Other contexts retain their existing versions; page schema remains 8. Existing popup coverage updates its version expectation where option inspection is now offered. No model configuration or inference runtime changes in this checkpoint.

## Prepared verification

Twelve methods in [research option-selection coverage](../../../host-mac/RemoteDesktopHostTests/ComputerUseBrowserResearchOptionSelectionTests.swift) specify:

1. Repeated native candidate discovery consumes no binding capacity and dispatches no event.
2. Metadata-only planning becomes a complete explicit scope; only offered native choices and accepted requirement references decode, and the request uses schema version 13.
3. The driver selects once, records a verified child journal, retains the complete task and reads fresh evidence before producing only a partial report.
4. A plain result-reading proposal after inspection retains the revalidated scoped date and composite state without another scope read.
5. An already-selected option is recorded as an observation with no input event.
6. Pause during inspection joins native completion, discards speculative selection authority and requires fresh observation after handback.
7. A paused attempted-but-unsent stage blocks other work; handback requires durable unsent retirement before a fresh stage, preserving old statuses and contract identity.
8. Pause during native dispatch retains historical confirmation across the original deadline and resumes without another click.
9. Failed attempt and failed retirement writes keep the original owner pending until an exact fresh store reconciles durability.
10. A changed observed date after unsent retirement cannot become the baseline of a replacement selection; old and current values remain distinguishable in context.
11. A handler that never establishes the requested selection stays uncertain, blocks further planner decisions and cannot resume after Stop.
12. Authentication before preparation emits no selection journal or effect; explicit handback preserves the goal and rejects the old proposal.

## Remaining repair order

1. Carry original criterion obligations across popup opening and other effects. A dropdown handler can overwrite a date before the first selection scope is read. The current popup receipt confirms opening/ownership, not preservation of other criteria. Capture the required baseline before that effect, retain its native identities and source obligations, and carry it through later plans. The new replacement-selection check cannot cover an obligation that was never captured or an intervening effect that is outside its history chain.
2. Reconcile changed or unavailable criteria explicitly across successful selections, form operations, fresh documents and login returns. Do not infer permission to replace a criterion from new page values. The conservative same-document guard can require intervention after a legitimate intentional change; an explicit goal-backed reconciliation is still needed.
3. Verify accepted application values and causally refreshed provider results after interactions. Selected flags, popup receipts and displayed input text do not independently prove travel dates, ticket class, fees, stock or booking availability. Complete offer predicates and honest unresolved results remain required.
4. Extend supported widgets and handler/navigation behavior without arbitrary-click or caption-matching fallbacks. Existing synthetic dispatch does not certify arbitrary page handlers, their network requests, transient changes between observations, virtualized/rebuilt option sets or unobserved state.
5. Complete durable parent task recovery after browser/process/session loss. The owner histories and native ledgers remain session-local; child journals alone cannot reconstruct them. Also qualify the larger context against the actual lightweight model and its fixed input/deadline limits.
6. Keep execution paused until authorized. After source readiness, qualify native/journal/owner integration, actual natural-language decisions, visible login handoff and real-site travel/concert/movie tasks. Measure failures and whole-app memory/thermal behavior before choosing a different model or adapting one on the authorized RTX 3080 desktop. SSH/hardware access and the 8 GB target remain unqualified. The broader [repair TODO](../../../TODO.md) stays open.
