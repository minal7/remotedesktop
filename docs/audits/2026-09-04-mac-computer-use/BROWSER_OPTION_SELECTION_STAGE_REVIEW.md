# Journaled option selection and original-baseline recovery

Source checkpoint following `2a1d262`. [The native selection foundation](BROWSER_OPTION_SELECTION_REVIEW.md) now has a journaled stage that retains its exact choice and observed criteria through interruption and failed writes. The ordinary action planner, research owner and driver do not yet expose this stage. The source remains uncompiled and unexecuted; there is no new model, provider or complete-task qualification.

Follow-up: [the option-selection driver review](BROWSER_OPTION_SELECTION_DRIVER_REVIEW.md) records subsequent source integration of scoped inspection, planner choices, owner exclusion, history and recovery. The statements and counts below describe this earlier stage checkpoint; execution and the broader remaining criteria/provider work are still pending.

## First-principles repair

A selection effect needs an identity before it starts. A timeout does not establish that the click failed, a visible file replacement does not establish durable storage, and an already-selected option does not need another click. Recovery must reconcile the original operation rather than construct an equivalent-looking replacement.

The original baseline also belongs in that identity. The previous native target digest included snapshot, binding and control IDs, but did not directly fingerprint the observed criteria values. A contract intended to preserve a date must distinguish the original date from a reconstructed baseline with a different value, even if the snapshot identifier were reused. The new digest freezes the complete observed baseline while leaving private values out of the journal.

## Implemented source path

- [The selection intent](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserOptionSelection.swift) now fingerprints the selected control and every retained observed criterion. The fingerprint includes complete metadata, sorted constraints, native option identities/labels/values/groups/flags, available form metadata and actual observed state. Optional values and variable-length lists use explicit presence/count fields under the existing length-prefixed hash. The selection payload uses namespace version 2 and includes that baseline digest and the original dispatch/no-event expectation. Action/page schemas remain 12/8. This performs no additional browser reads and stores no raw field values in the journal.
- Binding validation now checks its native ID, control, option and dispatch expectation consistently during preparation, receipt validation and stage construction. A mismatched or malformed binding cannot create a stage. The native ledger still binds actual objects and associated forms; a hash cannot recreate those objects after losing the browser session.
- [The new stage](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserOptionSelectionStage.swift) compiles one `browser.selectOption` step through [the shared execution engine](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseTaskExecution.swift). Its stage ID includes the root task, original root goal digest and sequence; its contract/effect fingerprint includes the exact target and baseline. The stage accepts sequences 0–31. Ownership and context are invariants, the original native selection binding is the precondition, and a validated historical selection receipt is the outcome.
- The engine acquires the journal execution lease and persists the attempt before native dispatch. The native adapter retains its own original operation before a click or already-selected observation. Repeating an attempted/uncertain stage takes the existing continuation path rather than invoking its first-attempt callback again. That path can start only the same original operation when the native ledger has no attempt and its original preconditions still hold; an existing attempt is acknowledged without another event.
- Native receipts remain separate from durable completion. The stage retains a confirmed native fact before later cancellation or a failed verification write can prevent publication. Its `observedReceipt` property does not authorize reporting success. `run` must finish the journal and current-owner checks before returning the receipt to its eventual research owner. A historical selection is still not proof of a current provider result or accepted backend value.
- Preflight, dispatch, receipt observation and pending-effect continuation join the actual DOM callback on error **inside** the execution lease. The outer run also joins before returning. This ordering covers cancellation and detached native callbacks; merely waiting after the execution engine returns would release its lease too soon. A permanently unresponsive document still requires the existing browser-close path to release outstanding native work.
- Confirmation retains the native dispatch-time window. Host receipt polling is capped at two seconds and can be shortened, including to one immediate query for prepared fixtures. Reopening keeps the original configured budget and original target. It cannot restart the native confirmation deadline. A previously captured native receipt remains an immutable historical fact after that window.
- Unsent retirement first acquires execution exclusion and checks the exact journal. Native proof must establish that the original operation never began, including an already-selected observation that sent no event. Only then can the stage write its retirement tombstone. Attempted/uncertain statuses are retained; verified work is not relabeled unsent. Native revocation without acknowledged disk durability leaves retirement pending.
- Failed writes require a fresh [journal store](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseTextStepStore.swift). Reopening is refused while the old run is executing or after it is retired. A replacement carries the exact target, sequence, operation and any already-observed receipt. The new lease reloads and reconfirms visible unretired progress before acting or publishing. A visible retirement tombstone reopens in retirement-only mode; it must be reconfirmed before its digest is returned. A fresh choice cannot reuse the old sequence/contract, including after retirement.
- Authentication errors before or after native dispatch remain typed. An authentication page before preflight cannot produce an attempt; an already-attempted operation cannot gain replay authority through login recovery. Actual manual takeover, explicit handback, refreshed target admission and task-history publication still need the retained research owner integration below.

## Prepared verification

Eleven methods in [selection-stage coverage](../../../host-mac/RemoteDesktopHostTests/ComputerUseBrowserOptionSelectionStageTests.swift) specify:

1. Different observed date values and choice qualifications produce different baseline fingerprints under the same snapshot ID; malformed/rebound bindings are rejected and durable journals exclude raw task/field/choice values.
2. Durable attempted state exists before the effect boundary; repeated completion does not repeat an event, and already-selected observations send no click.
3. Cancellation before native dispatch resumes only the original journaled operation, with the same baseline and effect identity after reopening.
4. Cancellation at native preflight, dispatch and receipt boundaries excludes competing journal ownership; the public call joins its native callback before returning, and a cached native fact can later confirm without replay.
5. A failed attempt replacement dispatches nothing; a rebound choice cannot use the same journal and a fresh exact store can reconcile the original operation.
6. A failed verified replacement retains native evidence but cannot publish through the poisoned store; a fresh lease reconfirms the original journal before returning completion.
7. Failed retirement publication keeps the stage pending; reopening cannot execute the tombstoned operation and must reconfirm the exact retirement before releasing it.
8. A handler that overwrites an observed date stays uncertain after reopening; recovery carries the original baseline rather than adopting the new value.
9. A replaced but never-clicked option can be durably retired; fresh preparation requires a new stage identity while preserving the original goal.
10. A late selection cannot restart the native confirmation window or become a false unsent retirement.
11. Authentication before and after an attempt retains the correct typed handoff boundary and journal state.

The existing nine native-selection methods remain selected. Their page and explicit goal/scope helpers are shared with the new cases. [The control fixture](../../../host-mac/RemoteDesktopHostTests/ComputerUseBrowserControlStateTests.swift) forwards the existing native-dispatch callback for prepared cancellation cases. No production callback-delay hook, physical input, live provider or model inference is added. These cases have not executed; the callback checks are prepared assertions, not measured race coverage.

Five changed/new Swift files pass syntax-only parsing. Five new fixture JavaScript variants pass `node --check`; no JavaScript executes. The [default inventory](../../../host-mac/AcceptanceFixtures/osatlas-deterministic-tests.json) selects **1,251 source methods**, and the [focused inventory](browser-control-state-inventory.json) selects **568**, with eleven additions and no removals. No typecheck, build, test assertion, app/browser/computer-use launch, model execution or held-out inspection/run occurs.
