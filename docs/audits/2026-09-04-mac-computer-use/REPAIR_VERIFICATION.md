Each edit receives the shared engine's durable operation identity, checks the current retained element and exact before-value/selection, records the operation before the setter, then dispatches the page's input event. A separate read proves the result; the setter's return does not. Repeated IDs cannot dispatch another event. Page handlers that revert the edit or change an unedited field prevent whole-task completion. Email inputs without selection APIs cannot acquire an invented caret through an earlier replace/append. Cancellation or a DOM deadline returns promptly but retains the dispatched script's occupied slot until its callback or context closure, since WebKit cannot retract a script already sent. A later task cannot overtake it. This bounds host concurrency; it does not promise that a script already dispatched is physically stopped when cancellation arrives.

## Source-bound planner candidate

The next candidate addresses the gap between a model's flat edit list and the user's complete request. Each requirement must copy consecutive source fragments whose tokens account for the entire current request in order. The host reconstructs those fragments from the original text, so spacing allowed in copied source does not normalize the actual input payload. Each proposed edit must bind an explicit field mention and exact value within that requirement. A quoted target occurrence cannot also be an input value; a value from another clause, a substring inside a payload marker, a fabricated target or duplicate use of the same binding is rejected before input. Distinct clauses preserve genuinely repeated edits. An explicit singular back-reference requires a unique target in the preceding edit requirement. Explicitly preserved fields cannot also be edited. Unsupported operations still require source coverage and prevent partial text execution.
