# Retaining verified form entries and accounting for unfinished work

Source checkpoint after `5553fc6`. Runtime and model qualification remain paused. The [working repair list](../../../TODO.md) remains open.

## First-principles problem

An ordered form stage can make partial progress. For example, Category was entered and independently verified, then City became stale or its attempted-state write failed before native input. Restarting the entire plan would repeat the first input and its page events. Calling the whole stage complete would silently omit City. Refusing all progress would strand work even when the original native ledger can prove that the remaining operation never began.

These are separate facts: what was planned, what was verified, what might have executed, and what remains to be done. A verified disk flag is a candidate for reconciliation, not a fresh native receipt. Matching values cannot establish input delivery. Absence proves no input only in the original non-evicting native ledger, with earlier calls joined and other runners excluded. Losing that ledger leaves the old operation unresolved.

The repair retains a verified prefix as historical work, revokes only the suffix proven unsent, and carries explicit unfinished-edit obligations into the next plan. Query preparation requires those obligations to be resolved. Partial history never becomes whole-stage or whole-request success.

## Source implementation

1. **Represent the exact retained scope.** [The text task](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseTextTask.swift) derives prefix requirements from the original immutable contract and exact journal identity, using only its contiguous verified steps and original compiled input IDs. Prefix values contain explicit unchanged constraints plus those completed entries. The requirements are marked incomplete and cannot pass through the ordinary completed-text query adapter. The browser stage must still establish native proof before adoption.
2. **Prove and revoke together.** [The isolated DOM dispatcher](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserDOM.swift) accepts optional retained-prefix requirements in its existing no-input retirement operation. It checks original document/ledger identity, retained native field objects, every original dispatched receipt, and explicit preservation. All suffix IDs must be absent from the original attempt map and disjoint from retained receipts. Only after every check succeeds does it revoke all suffix IDs synchronously. It never clears receipts, rewrites attempts or rediscoveries to manufacture absence.
3. **Retain historical criteria despite reparable value drift.** The host may permit changes only on previously edited, unpreserved native fields, using the existing repair inspection rule. A changed value does not invalidate the history of input, and it does not count as current success. The next planning observation marks every such field as a mandatory repair; query preparation admits no value-drift exception. Replaced required objects and changed explicit preservation still block recovery.
4. **Keep earlier requirements until a replacement is verified.** [The combined continuation](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormStage.swift) merges all prior criteria with verified current-prefix results. It updates sources only for the verified edits. An intended suffix revision may have excluded an older field from this stage's unchanged constraints; that older requirement must survive until its replacement is verified. This also handles a Category input resetting an earlier City value while a future City revision remains unsent.
5. **Persist suffix retirement without resetting history.** [The journal store](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseTextStepStore.swift) records a retirement digest and exact `retainedPrefixCount`, with the original statuses unchanged. Count must be positive and smaller than the plan, with precisely that verified prefix and a canonical unfinished suffix. Count without a marker, arbitrary changes of count/digest, normal saves, ordinary binding replacement and full-plan execution cannot revive it. The dedicated write requires the caller's active execution lease, exact compare-and-swap, atomic replacement and directory synchronization. Whole-stage no-input retirement keeps its separate rule refusing all verified steps.
6. **Recover ambiguous publication through the same capability.** The stage blocks old execution from the beginning of revocation until durable resolution. A failed write opens a fresh store under the same task lease. An exact persisted marker records earlier positive native proof and can resolve its durability without inferring anything from a newer ledger. Only then is the partial receipt cached. A late Pause can close the return while keeping those facts; explicit handback can publish the same cached receipt without input replay or duplicate history. Native calls are joined before releasing the lease.
7. **Require explicit unfinished-edit mapping.** [Form input](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchFormInput.swift) projects unfinished entries as `pending1`, etc., with historical public labels, kinds and exact original user sources. It does not expose private values, old native IDs or executable authority. [Proposal decoding](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserFormProposal.swift) requires a `resume` array whenever pending work exists. Every pending alias must appear exactly once and map to a distinct actual current edit. Missing entries, duplicate aliases/fields and mappings to preserved or unedited fields fail before effects. The replacement still needs its own current goal-backed payload. Questions and unavailable responses remain effect-free alternatives. A second interruption retains the unresolved sources again, deduplicated.
8. **Connect recovery to the normal driver.** [The research owner](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchTask.swift) records actual versus planned edit counts, retains the same adapter, and adds suffix-retirement history once. [The driver](../../../host-mac/RemoteDesktopHost/ComputerUse/ComputerUseBrowserResearchDriver.swift) attempts this prefix reconciliation before whole-stage retirement for the existing stale/uncertain recovery outcomes. The next plan has distinct stage/operation authority. The action context and native query adapter both withhold submission while unfinished work exists.

Form input is version 8, the form response schema is `browser_form_plan_v7`, the action context/schema is version 5, and the combined continuation digest is version 4. These prompts and schemas need model qualification. The host proves reference coverage and payload provenance; a model's resumption mapping is still a proposed semantic correspondence. It does not prove that an old label and a new field mean the same thing, or that a new answer was interpreted correctly.

## Follow-up repair order

1. **Native input that began but did not complete.** Do not issue a replacement effect merely because a value looks right or a step has become uncertain. Preserve the original operation and establish an outcome-reconciliation capability for incomplete dispatch tails and changed postconditions.
2. **Required object replacement.** A missing earlier edited/preserved object currently blocks continuation. Retain its historical receipt separately from the fresh object that represents the remaining user requirement. Require explicit correspondence and current semantics before acting.
3. **Obsolete criteria and revoked preservation.** Accepted clarifications may legitimately remove an earlier criterion or preservation rule. Require explicit source-backed revision; omission and resumption labels cannot silently release either one. The current one-to-one resumption mapping also declines changes requiring an unfinished edit to split across multiple fields or merge into one.
4. **Document and login transitions.** Preserve complete remaining-goal intent through redirects, provider windows, replaced documents and explicit user handback without lending old native bindings to a new page. Actual account/provider and phone/host behavior remains unqualified.
5. **Durable parent reconstruction.** Native task ownership and this combined form graph remain process-local. Do not imply that the child marker alone restores a browser session, task graph or pending-source intent after a host/browser crash.
6. **Broader browsing and answers.** Complete date/location/custom-widget handling, POST/JavaScript-driven forms, travel/concert/movie availability and fee predicates, distinct result counts, ranking and public source links. GET-form recovery is an intermediate capability.
7. **Qualification and model selection.** After correctness work reaches readiness and the user authorizes execution, run the controlled regressions, then qualify model interpretation separately. Alternative models and RTX 3080 desktop adaptation are authorized if evidence shows a need; SSH connectivity and remote hardware remain unverified. Distillation/pruning must preserve independent held-out evaluation and the 8 GB Mac target. Live website E2E still needs the later explicit permission already requested by the user.
